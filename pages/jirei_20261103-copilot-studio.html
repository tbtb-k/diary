AI活用事例Copilot Studio2026年11月3日／自治体（カナダ・モントリオール市）・住民向け問い合わせ

4万ページの市のサイトに、窓口に聞く前の「質問できる案内役」を置きました

モントリオール市のウェブサイトは1日に5万人以上が訪れ、ページ数は4万以上あります。目的の情報を探しにくく、コールセンターには基本的な質問が集中していました。

そこで市の IT 部門は、Copilot Studio（AI の会話エージェントを作る Microsoft のツール）で住民向けの案内役を作り、サイトに埋め込みました。外部の開発会社には頼まず、市の職員だけで作ったと紹介されています。

会話の85%以上は、サイトの内容にもとづく生成 AI の回答で対応し、市は効率の高さを90%、利用者の満足度を5点満点で4点超と公表しています。

01こんな場面、ありませんか

「ごみの収集日はいつだったかな」「あの手続きに何の書類が要るのかな」。調べようとして、自治体のサイトで迷った経験はないでしょうか。

モントリオール市でも同じでした。ページは4万以上、サイトの更新に関わる人は約700人。住民の質問は電話にも集まり、緊急の電話に集中したいコールセンターは、季節ごとの混雑にも悩んでいました。

02やってみたこと

Copilot Studio は、文章で指示を書くとエージェント（質問に答えて作業もする AI の担当者）を作れるツールです。モントリオール市は、公開サイトを「知識の元」に指定し、さらに内部の2つのシステムにつなぎました。

住民は自然な文章で質問します。答えは基本的にサイトの内容から作られ、収集日や市庁舎の営業時間のように変わりやすい情報は、API（システム同士が情報をやり取りする窓口）で最新の値を取ってきます。

  1. 公開サイトを知識の元として設定しました。最初は期待どおりの結果が出ず、検索エンジン Bing（Copilot Studio が公開サイトを調べるときに使う検索）の索引を増やす取り組みを始めました。
  2. サイトを AI が読みやすい形に整えました。折りたたまれた内容や、後から読み込まれる内容は読まれにくいため、見出しや営業時間の書き方をそろえました。
  3. 収集日と市庁舎の営業時間は API でつなぎました。「郵便番号」「区」は専用の項目（カスタムエンティティ）にして、住民の言い回しも現場の職員が追加しました。
  4. 利用状況は、標準の分析画面に加えて Power BI（グラフで見るツール）の画面でも見ました。

※ 手順の並びは、出典の「実装のアプローチ」の項目を読みやすく整理したものです。実際の作業順は公表されていません。

03どう変わったか

これまで

サイトが大きく、探しにくい情報があり、基本的な質問が電話に集まっていました。

いま

住民が文章で質問でき、会話の85%以上はサイトにもとづく生成 AI の回答で対応しています。

数字はすべてモントリオール市（Microsoft Learn の事例記事）が公表したものです。Bing に載る文書数は、取り組みから3カ月で約3倍になりました（開始時は1.5万件未満）。電話の件数がどれだけ減ったかは公表されていません。

04明日から試すには

  1. 自分の職場の問い合わせ（総務、情シス、人事など）から、よく聞かれる質問を10個書き出します。
  2. 答えが載っているページや資料が、AI に読ませやすい形か見直します（見出しがある、表記がそろっている、など）。
  3. Copilot Studio の試用環境で、そのページを知識の元にした小さなエージェントを作り、10個の質問を試します。

準備物は、答えの元になる公開ページか資料と、試す質問のリストです。Copilot Studio の使える範囲やライセンスは組織の契約や管理者の設定で変わるので、先に確認してください。

05つまずきやすいところ

サイトの作りが、AI の回答の質を左右しました

出典によると、折りたたまれた内容や後から読み込まれる内容は、エージェントから見えないことがありました。更新が反映されるまでの遅れもあるため、変わりやすい情報は API で取る方がよいと紹介されています。

住民向けの案内役は、間違った答えがそのまま届きます。市はやり取りから個人情報を取り除く仕組みを置いています。社内で真似するときも、答えてよい範囲と、人につなぐ条件を最初に決めてください。

06おわりに

この事例の学びは、AI を入れる前に「答えの元になる文書を整える」ことが効く、という点です。これは問い合わせ対応に限らず、社内の手引きや FAQ 全般に当てはまります。

自分の職場に置き換えると、社内の手引きやよくある質問のページは、AI が読める形になっているでしょうか。営業時間や締め切りのように変わりやすい情報は、文書ではなく元のシステムから取る形も考えられます。
