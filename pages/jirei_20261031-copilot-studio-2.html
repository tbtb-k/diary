AI活用事例Copilot Studio2026年10月31日／決済サービス（Nexi Group）・カスタマーサポート

カード会社の問い合わせ窓口に、1日3,000件以上に答えるチャット担当ができました

欧州の決済会社 Nexi Group のコンタクトセンターでは、膨大なカードの資料を、担当者が手で探しながらお客様に答えていました。

そこで Copilot Studio（コードをほとんど書かずに AI エージェントを作れる Microsoft のツール）と Azure の AI 機能で、自社サイト上の会話型エージェントを作りました。

現在は1日3,000件以上のやり取りに対応し、満足度は70%です。人への引き継ぎも大きく減ったと説明されています。

01こんな場面、ありませんか

お客様から「このカードの再発行はどうすればいいですか」と聞かれ、担当者が何種類もの資料をめくって探す。同じようなカードでも条件が少しずつ違い、答えるまでに時間がかかる、という場面はないでしょうか。

Nexi は25の国と地域でカード事業を支えています。カードの種類や契約条件が多く、情報も複数の場所に散らばっていました。担当者は手作業で探す必要があり、対応時間が延びて、一定の品質で素早く答えるのが難しい状態でした。

02やってみたこと

Nexi のエージェントは、同社のサイト上でお客様と自然な言葉で会話します。カードの停止や再発行、取引の一覧表示といった手続きも、会話の中で進められます。

資料の検索には、Azure AI Search（検索の仕組み）と Azure OpenAI を使い、カードの等級などの情報を付けて資料を整理しました。社内システムとのやり取りは、Azure Functions と Key Vault（パスワードなどの保管庫）で安全につないでいます。

  1. お客様がチャットで質問します。サイトの利用者は、最初はログインなしで一般的な情報を聞けます。
  2. カードごとの手続きが必要なときは、ログインを求められます。
  3. 資料に関する質問は検索で答え、カードの停止や再発行は社内システムにつないで実行します。
  4. 回答で足りないときは、会話の内容を保ったまま担当者（Genesys Cloud）に引き継ぎます。

※ 4つのステップは公開記事の流れにそっています。画面の細かな設定や、使われている資料の中身は公開されていません。

03どう変わったか

これまで

担当者が複数の資料を探して答えていました。手続きの案内も手作業が中心でした。

いま

エージェントが等級に合った情報で答え、停止や再発行などの手続きも会話の中で進められます。

1日3,000件以上のやり取りと、満足度70%は、Nexi が Microsoft Learn の事例で公表した数字です。引き継ぎの件数が減ったとありますが、減少の割合は公表されていません。Nexi は今後、やり取りの記録から満足度の低かった質問を自動で見つけ、資料の抜けを報告するエージェントを作る計画です。

04明日から試すには

  1. よく聞かれる質問と、答えの根拠になる資料を10件ほど選びます。
  2. Copilot Studio でエージェントを作り、その資料だけをもとに答えるようにします。
  3. 答えられない質問は人に渡す道筋を、最初から決めておきます。

Copilot Studio の利用にはライセンスが必要です。Nexi は Azure の検索機能なども併用しており、同じ構成が必要かどうかは組織によって変わります。まずは小さく始めてください。

05つまずきやすいところ

検索を工夫しないと、答えがぶれる

Nexi は、単に資料をアップロードするだけでは足りないと考えました。カードの等級などの情報を付けて資料を整理し直すことで、似た資料が重なっても、お客様に合う答えが出るようにしたと説明されています。

カードの停止のような手続きは、本人確認を必ず通してから実行する設計になっています。社内で真似するときも、個人情報に関わる操作は、ログインや権限の確認を先に入れてください。AI の回答が間違うこともあるため、引き継ぎの道筋を残すことが大切です。

06おわりに

この事例は、問い合わせ対応だけでなく、「資料が多くて探すのが大変」という問題全般に使える形です。ポイントは、答える範囲を絞り、答えられないときは人に渡すところまで先に決めたことです。

自分の職場に置き換えると、社内のヘルプデスクを思い浮かべてください。就業規則、経費精算、IT の手順書など、資料はたくさんあるのに探しにくい場面は多いはずです。最初の1テーマだけ、同じ形で試せないか考えてみてください。
