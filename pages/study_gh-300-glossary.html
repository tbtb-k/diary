Overview

GH-300 ってどんな試験？

料金・時間・合格点などの基本情報と、何が問われるかをまとめました。数字は 2026-11-26 に公式ページで確認したものです。

ひとことで言うと「GitHub Copilot を安全に、上手に使いこなせるか」を確かめる試験です

GH-300 は、GitHub の認定資格「GitHub Copilot」を取るための試験です。受験者像は、Copilot を使ってソフトウェア開発の生産性・品質・セキュリティを上げられる人。責任ある AI の使い方、プロンプトの工夫、プランごとの機能、プライバシーを守る設定が範囲に入ります。GitHub の基本に慣れていて、何かのプログラミング言語の経験があることが前提です。最近の版では、Copilot CLI、エージェントモード、サブエージェント、MCP、組織のポリシーや監査ログといった項目が加わっています。[1][2]

Copilot と生成 AI の基本

GitHub Copilot★ 重要GitHub Copilot

GitHub の AI コーディング支援です。エディター（IDE）、GitHub.com、GitHub Mobile、ターミナル（Copilot CLI）、デスクトップの Copilot アプリで使えます。コードの候補を出す、質問に答える、作業を任されて変更まで進める、PR をレビューする、と役割が広がっています。

ツボ受験者像は「Copilot で開発の生産性・品質・セキュリティを上げられる人」。責任ある使い方、プロンプト、プランごとの機能、プライバシーの守り方まで問われます。

[1][22]

生成 AI★ 重要Generative AI

学習したパターンをもとに、文章やコードを新しく作り出す AI です。確率で次の言葉を選ぶので、同じ質問でも答えが変わったり、もっともらしい間違いを出したりします。

ツボ分野1の出発点です。「便利だが間違えることがある」から「人が確かめる」につながります。

[1][57]

大規模言語モデル（LLM）★ 重要Large language model

大量のテキストで学習したモデルで、Copilot の頭脳にあたります。今のファイルだけでなく、開いている他のファイルやタブも手がかりにして候補を作ります。

[9]

プロンプト★ 重要Prompt

Copilot への指示です。チャットに打つ文章だけでなく、コードの中の自然言語のコメントや、書きかけのコードそのものもプロンプトになります。

[7][6]

コンテキスト（文脈）★ 重要Context

答えを作るときに Copilot が参考にする周りの情報です。カーソルの前後のコード、ファイル名と種類、開いているタブ、プロジェクトの構成などが含まれます。

ツボ「提案がずれる」→ まず文脈が足りているかを疑うのが定石です。

[7]

トークンToken

モデルが文字を扱う単位です。いまの課金は、入力・出力・キャッシュのトークン量と使ったモデルで決まります。

[20]

コンテキストウィンドウ★ 重要Context window

モデルが一度に読める量の上限です。長い会話や大きなファイルは入りきらず、古い部分から外れていきます。Copilot CLI は上限の95%に近づくと会話を自動で要約（圧縮）します。

ツボ大きな課題は小さく分けて頼む、が対策の答えになりやすいです。

[8][24]

ハルシネーション★ 重要Hallucination

もっともらしいのに事実と違う出力です。存在しない関数やライブラリ、間違った説明をそれらしく出すことがあります。

[57][14]

エージェント★ 重要Agent

目標を渡すと、計画を立て、ツールで実行し、結果を見て直すところまで進める AI です。答えを返すだけのチャットや、決まったきっかけで動くオートメーションとは区別されます。

ツボどれだけ任せても、目標と制約を決めて結果を確かめる責任は人にあります。

[22]

IDE（統合開発環境）Integrated development environment

コードを書くためのアプリです。Copilot は Visual Studio Code、Visual Studio、JetBrains 製品、Xcode、Eclipse、Vim／Neovim などで使えます。機能の対応は IDE ごとに少しずつ違います。

[27][48]

プランとお金

Copilot のプラン★ 重要Copilot plans

個人向けは Free・Student（無料）、Pro（月 $10）、Pro+（月 $39）、Max（月 $100）。組織向けは Business（1席 月 $19）と Enterprise（1席 月 $39）、対象企業向けの Copilot access があります。

ツボ「組織で一括管理・ポリシー・コンテンツ除外」と出たら Business／Enterprise です。個人プランではコンテンツ除外は使えません。

[19]

Copilot FreeCopilot Free

無料プランです。補完は月2,000回まで、モデルは自動選択だけ。組織やエンタープライズから Copilot をもらっている人は使えません。

[19][20]

Copilot Business★ 重要Copilot Business

組織向けのプランです。1席 月 $19 で、1人あたり月 1,900 AI クレジットが組織の共有プールに入ります。ポリシー管理、コンテンツ除外、組織のカスタム指示が使えます。

ツボIP 補償や「データを学習に使わない」約束の対象にもなります。

[19][10][51]

Copilot Enterprise★ 重要Copilot Enterprise

GitHub Enterprise Cloud を使う企業向けのプランです。1席 月 $39 で、Business の機能すべてに加え、より多い AI クレジットと新しいモデル・機能の優先利用がつきます。

[19]

GitHub AI Credits（AI クレジット）★ 重要GitHub AI Credits

2026年6月1日に始まった、使った分だけ数える課金の単位です。1 クレジット＝$0.01。使ったモデルとトークン量で消費量が決まります。毎月1日（UTC）にリセットされ、余りは繰り越せません。

ツボインライン提案（補完）と次の編集候補はクレジットを消費せず、有料プランでは無制限です。

[20][21]

プレミアムリクエスト（旧方式）★ 重要Premium requests (PRU)

2026年5月までの課金の単位です。1回のやり取りを1リクエストと数え、強いモデルほど大きい「倍率」をかけていました。今は、以前からの年額プランを続けている個人だけがこの方式です。

ツボ古い教材や問題文に出ることがあります。いまの「AI クレジット」と同じ役割の言葉だと読み替えれば迷いません。

[21]

シート（席・ライセンス）Seat

組織が個人に割り当てる Copilot の利用権です。Business／Enterprise は割り当てた席の数で課金されます。割り当ては画面のほか REST API でも管理できます。

[19][56]

モデル

モデルの選択Model selection

チャットやエージェントで使うモデルを選べます。難しい推論が得意なモデルほど高く、軽いモデルは安くて速いです。使えるモデルはプランと管理者のポリシーで決まります。

ツボクレジットを節約したいとき → 軽いモデルに切り替える、が公式の説明です。

[20][19]

自動モデル選択Auto model selection

Copilot が場面に合うモデルを選んでくれる仕組みです。Free と Student のプランでは、モデルはこの自動選択だけになります。

[43][19]

ファインチューニングFine-tuning

学習済みのモデルを、特定の用途の少ないデータで追加学習させて、その用途に合わせることです。

[9]

LoRA（低ランク適応）Low-Rank Adaptation

モデル全体を学習し直す代わりに、小さな学習用の部品だけを足して調整する方法です。元のモデルはそのままなので、時間と計算資源を節約できます。Learn の教材では GitHub が使っている方法として紹介されています。

[9]

GA とプレビューGeneral availability / Preview

GA は正式提供、プレビューはお試し提供です。試験はおもに GA の機能から出ますが、よく使われているプレビュー機能が出ることもあります。

[1]

責任ある AI の6原則

責任ある AI★ 重要Responsible AI

AI を安全に、信頼でき、倫理的なやり方で作って使うための考え方です。Microsoft と GitHub は6つの原則を掲げていて、GitHub の Copilot の説明書（Application Card）もこの原則にそっています。

ツボ6原則の名前と中身の組み合わせがそのまま出やすいです。

[5][57]

公平性★ 重要Fairness

AI はすべての人を公平に扱うべき、という原則です。偏ったデータで学習すると、偏った結果が出ます。

[5]

信頼性と安全性★ 重要Reliability and safety

AI は想定どおりに、安全に動くべき、という原則です。

[5]

プライバシーとセキュリティ★ 重要Privacy and security

AI は安全で、プライバシーを尊重すべき、という原則です。必要なデータだけを集め、同意を取り、個人情報は匿名化するといった対策が挙げられています。

[5]

包括性（インクルーシブネス）★ 重要Inclusiveness

AI はすべての人に力を与え、参加できるようにすべき、という原則です。

[5]

透明性★ 重要Transparency

AI の仕組みや限界が、使う人に理解できるようにすべき、という原則です。

[5][57]

アカウンタビリティ（説明責任）★ 重要Accountability

AI システムには人が責任を持つべき、という原則です。

ツボ「Copilot が書いたコードの責任はだれに？」→ 採用した人（開発者・組織）です。AI に責任は移りません。

[5][22]

リスクと対策

生成 AI のリスクと限界★ 重要Risks and limitations of generative AI

判断の理由が見えにくい、意図しない有害な結果を出す、間違える、偏る、といったリスクがあります。対策として、ガバナンス（ルールと監督）、透明性、人による監督が挙げられています。

[5][1]

バイアス（偏り）★ 重要Bias

学習データの偏りや誤りが提案に表れることです。特定の言語や書き方に寄ったり、古いやり方を出したりします。

[57][14]

安全でないコード★ 重要Insecure code

動きそうに見えても、脆弱性を含むコードが提案されることがあります。認証や入力の処理など、セキュリティに関わるコードは特に念入りに確認します。

[57][14]

不正確なコードInaccurate code

文法的にも意味的にも正しそうに見えて、実は間違っている、または意図と違うコードのことです。レビューとテストで確かめます。

[57]

人による確認（ヒューマン・イン・ザ・ループ）★ 重要Human oversight / Human in the loop

AI の出力をそのまま使わず、人が見て判断する仕組みです。インライン提案は、人が受け入れない限りコードに入りません。エージェントの変更も人がレビューしてから取り込みます。

ツボ責任ある使い方の問題では、ほぼ必ず正解の側に入る考え方です。

[57][22][5]

AI の出力を検証する★ 重要Validate AI output

提案をそのまま信じず、読んで理解し、テストし、セキュリティやライセンスを確かめることです。もっともらしく見えても間違っていることがあるためです。

[1][57]

潜在的な害と軽減策Potential harms and mitigation strategies

誤ったコード、偏り、脆弱性、公開コードとの一致、個人情報の混入などが「害」の例です。軽減策は、人による確認、フィルター、ポリシーでの制御、テストなどです。

[1][57][7]

Application Card（アプリケーションカード）Application card

GitHub が Copilot の機能ごとに公開している説明書です。用途、限界、評価の方法、安全策、使い方のコツがまとまっています。

[57]

ガバナンスGovernance

ルール、権限、監督の仕組みで AI のリスクを管理することです。Copilot では、ポリシー、監査ログ、コンテンツ除外などが道具になります。

[5][52]

GitHub Copilot の機能を使う

いちばん配点が大きい分野です。IDE、Copilot CLI、GitHub.com のエージェント、カスタマイズ、組織の管理まで範囲が広いので、「どの機能がどこで何をするか」を整理して覚えましょう。

IDE で使う

IDE で Copilot を有効にする★ 重要Enable Copilot in the IDE

IDE に Copilot の拡張機能（プラグイン）を入れ、GitHub アカウントでサインインすると使えます。IDE の設定やステータスのアイコンから、全体または言語ごとに有効・無効を切り替えられます。

[29][27]

インライン提案（ゴーストテキスト）★ 重要Inline suggestions / Ghost text

入力中に灰色の文字で出るコードの候補です。Tab で確定、Esc で却下、Alt＋]／Alt＋[（Mac は Option）で別の候補を見られます。

ツボ課金やプランの説明では「コード補完（completions）」とも呼ばれます。

[28][15]

次の編集候補（NES）★ 重要Next edit suggestions

いまの編集の流れから、次に直しそうな場所と内容を予測して出す機能です。Tab で候補の場所に移動し、もう一度 Tab で確定します。

ツボインライン提案と同じく、AI クレジットを消費しません。

[28][19]

Copilot Chat★ 重要Copilot Chat

会話で質問したり、説明や修正を頼んだりする機能です。IDE、GitHub.com、GitHub Mobile、Windows Terminal で使えます。

[19][33]

インラインチャットInline chat

エディターの中、コードのすぐそばで開く小さなチャットです。チャット画面に切り替えずに、その場で直しを頼めます。

[16][19]

スラッシュコマンド★ 重要Slash commands

/ で始まる短い命令です。/explain（説明）、/fix（修正案）、/tests（テスト生成）、/doc（ドキュメント）、/new（新規プロジェクト）、/clear（新しい会話）などがあります。使えるコマンドは IDE ごとに違います。

ツボ「長いプロンプトを書かずに定番の作業を頼む」ための仕組み、と覚えます。

[33]

チャット参加者（@）★ 重要Chat participants

@ で呼ぶ、得意分野を持つ相手です。VS Code では @github（GitHub の情報）、@terminal（ターミナル）、@vscode（VS Code の操作）、@azure（プレビュー）が代表例です。

[33]

チャット変数（#）★ 重要Chat variables

# で文脈を指定する書き方です。#file（ファイル）、#selection（選択範囲）、#function（関数）などのほか、#codebase でワークスペース全体から関係する部分を探させられます。

[33][15]

Ask・Agent・Plan★ 重要Ask / Agent / Plan

チャットで選ぶ動き方です。Ask はコードを変えずに理解する、Agent は変更して検証まで進める、Plan は計画だけを作って承認を待つ、という使い分けです。

[16][31][30]

エージェントモード★ 重要Agent mode

大まかな作業を渡すと、関係するファイルを特定し、編集し、ビルドやテストのコマンドを実行して、うまくいくまで繰り返すモードです。コマンドは既定で実行前に承認を求めます。

[30][17]

プロンプトが処理される流れ★ 重要Prompt process flow

モデルの出力を届ける前の最終チェックです。有害な内容を取り除き、コードの品質（XSS や SQL インジェクションのような典型的な脆弱性）を確かめ、設定があれば公開コードとの一致もチェックします。不合格の部分は切り詰めるか捨てます。

4つの S★ 重要The 4 S's

Single（1つの課題に絞る）、Specific（具体的に書く）、Short（短く簡潔に）、Surround（わかりやすいファイル名にし、関係ファイルを開いて周りを整える）の4つです。

ツボLearn の教材が「プロンプトの原則」として挙げる、いちばん基本の型です。

[6]

プロンプトの構成要素Prompt structure

目的（何をしてほしいか）、文脈（どのコード・どの前提で）、条件や制約、例、出力の形、を意識して組み立てます。足りないと、Copilot は推測で埋めます。

[6][1]

ゼロショット★ 重要Zero-shot prompting

例を見せずに頼む方法です。モデルがもともと知っていることだけで答えるので、よくある定番のパターンに向いています。

[6]

ワンショットOne-shot prompting

例を1つだけ見せて頼む方法です。自分たちの書き方にそろえたいときに効きます。

[6]

フューショット★ 重要Few-shot prompting

例を複数見せて頼む方法です。いくつものケースやエッジケースを扱う、手の込んだ実装に向いています。

ツボ「例の数」で見分けます。ゼロ＝0個、ワン＝1個、フュー＝数個。

[6]

例を示すProvide examples

入力と出力の例を見せると、求めるパターンが伝わりやすくなり、最初から狙いに近い提案が出ます。

[6]

ロールプロンプトRole prompting

「セキュリティの専門家として」のように、役割を指定して頼む方法です。専門分野に寄せた、質の高い答えが出やすくなります。

[6]

コメントで指示するNatural language comments

コードの中に「// 代替テキストのない画像をすべて探す」のようなコメントを書くと、それがプロンプトになり、続きのコードが提案されます。

[7][28]

アサートとイテレート★ 重要Assert and iterate

1回目で完璧を求めず、出てきたものを見て、指示に詳しさや例を足して頼み直す進め方です。一からやり直すより早く、質の高いコードにたどり着けます。

[6]

問題を小さく分ける★ 重要Break down complex problems

大きく複雑な課題は、小さく焦点を絞った質問に分けます。コンテキストウィンドウの制限があるので、分けたほうが正確な答えが返ります。

[8][6]

文脈と会話の履歴

文脈の決まり方★ 重要How context is determined

Copilot は、カーソル位置の周り、開いているファイル、チャットで指定したファイルや選択範囲、会話の履歴、カスタム指示などから文脈を組み立てます。自分から文脈を足すほど、答えはプロジェクトに合ってきます。

[7][8][34]

文脈を足す（#・@・添付）Adding context

#file、#selection、#codebase などのチャット変数や、ファイルの添付、@ での参加者の指定で、答えの根拠になる情報を渡します。

[15][16][33]

チャット履歴★ 重要Chat history

それまでの会話は、次の答えの文脈として使われます。話が長くなると効率が落ち、AI クレジットも多く使います。要約して渡す、話題が変わったら新しい会話にする、が対策です。

[8][6]

チェーンプロンプトChain prompting

「関数を作る → エラー処理を足す → テストを足す → コメントを足す」のように、会話を重ねて段階的に仕上げる進め方です。

[6]

新しい会話を始める（/clear）Start a new chat

話題が変わったら会話をリセットします。前の話が混ざらず、必要な前提だけを短く渡せます。

[33][6]

Domain 6 · 10–15%

プライバシー・コンテンツ除外・セーフガードの設定

見せたくないファイルを Copilot から外す設定、公開コードとの一致への備え、うまく動かないときの直し方を問う分野です。「だれが・どこで・何を設定するか」をはっきりさせましょう。

コンテンツ除外

コンテンツ除外★ 重要Content exclusion

指定したファイルを Copilot に使わせない設定です。除外したファイルではインライン提案が出ず、その内容は他のファイルの提案やチャットの答えにも使われず、Copilot のコードレビューの対象からも外れます。

ツボ使えるのは Copilot Business と Enterprise です。

[48][19]

除外を設定できる人★ 重要Who can configure content exclusion

リポジトリ管理者は自分のリポジトリ、組織のオーナーは組織から席をもらっている人、エンタープライズのオーナーはエンタープライズの全員に対して設定できます。

[48]

除外パスの書き方Path syntax

リポジトリの設定では - "/scripts/**" のように1行に1パスで書きます。fnmatch の書き方が使え、大文字・小文字は区別されません。組織の設定ではリポジトリを指定してからパスを書き、"*": で全リポジトリが対象になります。

[49]

コンテンツ除外の限界★ 重要Limitations of content exclusion

除外はファイルを守る「セキュリティの壁」ではなく、GitHub の道具向けのガードレールです。シンボリックリンクとリモートのファイルシステム上のリポジトリには効きません。IDE が間接的に渡す型の情報などは使われることがあり、他社の MCP サーバーやクライアントでは守られる保証がありません。

ツボXcode と Eclipse では、チャットとエージェントは除外に対応していません（インライン提案は対応）。

[48]

除外の反映（最大30分）★ 重要Propagating content exclusion changes

除外を追加・変更してから、すでに設定を読み込んでいる IDE に反映されるまで最大30分かかります。すぐ反映したいときは、VS Code ならコマンドパレットの「Developer: Reload Window」、JetBrains と Visual Studio はアプリの再起動です。

ツボ「除外したのに提案が出る」→ まず反映待ちを疑います。

[49]

公開コードと権利

公開コードと一致する提案のブロック★ 重要Suggestions matching public code

GitHub 上の公開コードと一致する提案を「Block（出さない）」か「Allow（出す）」かを選ぶ設定です。インライン提案では、候補と周り約150文字を公開コードの索引と比べます。個人は自分の設定、組織は管理者が全員分を決めます。

ツボ組織から席をもらっている人は、自分で変えられません。複数の組織の設定が違うときは「最も厳しい」設定になります。

[27][51][7][53]

コード参照★ 重要Code referencing

Allow にしているとき（または Block に対応していない製品のとき）、一致した公開コードのリポジトリとライセンスの情報を表示する機能です。出どころとライセンスを見て、使う・出典を書く・消すを判断します。

ツボJetBrains ではログファイルの [Public Code References] で確認できます。

[27][50]

IP 補償★ 重要IP indemnity

Copilot の提案を使ったことで知的財産の請求を受けたときに、法的に守ってもらえる契約上の保護です。Copilot Business と Enterprise に含まれます。

ツボLearn の教材では、組織で公開コードと一致する提案をブロックしていることが条件とされています。

[10]

データ保護契約（DPA）Data Protection Agreement

データをどう守るかを定めた契約です。Business と Enterprise のデータを、顧客の許可なく学習に使わないこともここで定められています。

[10][51]

出力の扱いと限界★ 重要Ownership and limitations of outputs

Copilot の出力を採用するかどうか、ライセンス上問題がないかの判断は、使う側に任されています。公開コードとの一致はコード参照で出どころとライセンスを確かめ、権利の細かい扱いは契約（製品の利用条件や DPA）と Trust Center で確認します。

[1][27][10]

エディターの設定とトラブル対応

エディターの設定★ 重要Editor settings

IDE ごとに、Copilot を全体または言語ごとに有効・無効にしたり、提案の出し方を変えたりできます。JetBrains ではステータスアイコンから「全体で無効」か「この言語だけ無効」を選べます。

[29]

提案が出ないときの確認★ 重要Troubleshooting missing suggestions

ネット接続、拡張機能が最新か、IDE が対応しているか、そのファイルがコンテンツ除外されていないか、を順に確かめます。

[11]

提案の質が低いときの対処Improving unsatisfactory suggestions

わかりやすいコメントや名前で文脈をはっきりさせる、プロンプトの長さや詳しさを調整する、関係ファイルを開く、などで改善します。

[11][6]

ファイアウォールと許可リストFirewall allowlist

会社のファイアウォールが Copilot の通信を止めると、うまく動きません。必要な URL・ポート・プロトコルを許可リストに入れて通します。

[11]

除外が効かないときの対処Troubleshooting content exclusions

反映に最大30分かかるので待つか再読み込みする、パスの書き方を見直す、シンボリックリンクやリモートのファイルシステムではないか確かめる、の順で確認します。

[49][48][11]
