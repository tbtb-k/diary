AI活用事例Agent Builder2026年9月28日／不動産（東京建物）・現場部門の資料検索

マニュアル探しを、現場が自作したエージェントに任せられるようになりました

東京建物では、担当物件のフォルダを探して資料や契約条項を確かめる作業が多く、必要な情報にたどり着くまで時間がかかっていました。

そこで、プログラムを書かずにエージェントを作れる「Agent Builder」だけを、あえて社内に広めました。

賃貸マンション部門ではマニュアルを高速に検索できるエージェントが生まれ、全社では1年弱で約500体が現場から作られています。

01こんな場面、ありませんか

「あの手続き、マニュアルのどこに書いてあったかな」と、共有フォルダを何階層もたどった経験はありませんか。案件や物件ごとにフォルダが分かれていると、目当ての資料を開くまでに時間がかかります。やっと見つけても、分厚いマニュアルの中から該当箇所を探す作業が残っています。

東京建物でも、部署や案件ごとに業務の流れやデータの置き方が違い、「その人にしか分からない」状態（属人化）が進んでいました。担当する物件のフォルダを探しに行き、資料や契約条項を確認する作業が頻繁に発生していたそうです。異動のときの引き継ぎも、スムーズにはいっていませんでした。

02やってみたこと

使ったのは、Microsoft 365 Copilot に組み込まれている「Agent Builder（エージェント ビルダー）」です。エージェントとは、特定の仕事のために、役割と参照する資料をあらかじめ決めておいた専用の Copilot のことです。Agent Builder では、作りたいものを日本語で説明するだけで、プログラムを書かずにエージェントを作れます。

東京建物には、より高度なエージェントを作れる Copilot Studio もありました。それでも社内には、あえて簡単な Agent Builder だけを周知しました。「難しそう」という現場の抵抗感を下げるためです。賃貸マンションの開発・運営を担う部門は、これまで蓄積・整理してきたマニュアルや資料を読み込ませました。質問すると、該当箇所を探して答えてくれるエージェントです。

  1. 部門でこれまで蓄積・整理してきたマニュアルや資料を用意します。
  2. Copilot の画面から Agent Builder を開き、「このマニュアルをもとに質問に答える」といった役割を日本語で伝えます。
  3. 参照先としてマニュアル・資料を指定し、試しに質問して答え方を確かめます。
  4. できたエージェントは、社内イントラネット（SharePoint 上）の業務掲示板で部署ごとに公表し、ほかの人も使えるようにしました。

※ 手順2・3は、Agent Builder の一般的な作り方で補っています。東京建物が実際に使った指示文は公開されていません。

03どう変わったか

これまで

担当物件のフォルダを探しに行き、資料や契約条項を自分で確認していました。必要な情報にたどり着くまでに、案外時間がかかっていました。

いま

フォルダをたどる代わりに、まずエージェントに質問するところから始められます。読み込ませたマニュアル・資料から、該当しそうな箇所を探して答えてくれます。

同じ形のエージェントは、ほかの部署にも広がりました。ビル開発技術部門は、特定の会議の過去の議事録を読み込ませ、長く続くプロジェクトの経緯を追えるエージェントを作りました。人事部は、寄せられる問い合わせに担当者が関連規程をすぐ参照できるエージェントを作っています。

全社では、全社展開から1年弱で約500体のエージェントが現場部門から生まれました。Copilot の利用率は月間アクティブで平均約80％です。全社アンケートでは、7割以上が「業務効率化に寄与している」と回答しています。これらは東京建物が公表した、Copilot 全体についての数字です。マニュアル検索エージェント単体での時間短縮の数字は、記事では公表されていません。

04明日から試すには

  1. 「よく探しに行く資料」を1つ決めます。部署の手順書や規程集など、何度も同じところを開いているものがおすすめです。
  2. Microsoft 365 Copilot を開き、「エージェントの作成」から Agent Builder を起動します。「この手順書をもとに、手続きの質問に答えてください」と役割を書き、その資料を参照先に指定します。
  3. 自分がよく聞かれる質問を3つ投げて、答えと根拠の箇所が合っているか確かめます。合っていれば、まずは自分用として使い始めます。

準備するのは、参照させたい資料だけです。画面の表記や使える機能は、ライセンスや社内の設定、時期によって変わります。見当たらない場合は、社内の IT 担当に確認してみてください。

05つまずきやすいところ

最初から精度を追いすぎないこと

東京建物は、精度を求めて独自のツールを作り込むのではなく、まず標準の機能を使う方針にしました。独自ツールは、参照するデータや AI モデル（中で文章を考えている頭脳）が変わるたびに調整が必要で、運用が重くなるためです。社員への周知も「確実に業務で使われる機能」に絞り、「教えすぎない」ようにしています。

エージェントが増えるほど、「誰が何を見られるか」の管理が大切になります。東京建物は、Microsoft Entra ID（社員のアカウントと権限を管理するしくみ）にもとづくアクセス権限で情報を管理し、内部統制を保っています。エージェントを人と共有するときは、参照させた資料を相手が見てもよいか、先に確認してください。

また、エージェントの答えには間違いが混ざることがあります。規程や契約に関わる判断は、答えに出てきた元の資料で確認してから使うようにしてください。

06おわりに

ポイントは、高機能なツールを使ったことではありません。いちばん簡単な道具だけを見せて、あとは現場に任せたことです。教えることを絞ったからこそ、自分の仕事の困りごとを一番よく知っている人が、自分でエージェントを作り始めました。この「まず簡単な型を1つだけ渡す」考え方は、新しいツールを社内に広めるときにも応用できます。

自分の職場に置き換えると、部署ごとの手順書や規程集がある職場なら、同じ形のエージェントをすぐに作れます。まずは自分用の1体から始め、便利だったら部署の掲示板などで共有する流れがおすすめです。
