Cowork in Edge for Business
何ができて、何が危なくて、どこで設定するか

Microsoft 365 Copilot の「Cowork」が、社員のパソコンの Microsoft Edge を使って、Web サイト上の作業を代わりに進める機能です。2026年11月の Ignite で一般提供（GA）が発表されました[3]。この記事では、仕組み・オンにしたときのリスク・Microsoft 365 管理センターと Edge のポリシーでの設定を、公式ドキュメントを根拠に整理します。

調査日
2026-11-23
対象
Copilot Cowork のブラウザー利用（一般の商用テナント向け。米国政府向け GCC は別扱い）
根拠
Microsoft Learn・メッセージセンター・Microsoft 公式ブログなど 15件（うち第三者 2件）

結論

社員の Edge を「本人として」操作できる強力な機能なので、既定はオフです。オンにするなら「誰に」「どのサイトで」「いくらまで」を先に絞って、小さなグループから始めるのが安全です。

  1. Cowork は本人と同じサインイン状態・同じ権限で動きます。本人より広い範囲には届きませんが、本人ができることは基本的に全部できます[1]。
  2. サインイン・MFA・CAPTCHA・支払いは人に戻し、重要な送信は承認カードで止まる、という歯止めは公式に用意されています[1][6]。一方で、Web ページに仕込まれた「隠れた指示」（プロンプトインジェクション）への具体的な対策は、Cowork の公式資料には書かれていません記載なし。
  3. 設定は大きく3か所に分かれます。どこか1か所だけでは絞り切れません。

先に押さえておきたい言葉

Cowork
Microsoft 365 Copilot の中で、複数ステップの仕事を自分で段取りして進める仕組みです。Microsoft は「エージェントとは別の、エージェント的なシステム」と説明しています[2]。
ブラウザー利用
（Browser use）
Cowork が Edge を開いて、クリックや文字入力を代わりに行うことです。この記事の主役です。
従量課金
（usage-based billing）
使った分だけ組織に請求される仕組みです。Cowork はこれを有効にしないと使えません[2]。
支出ポリシー
（spending policy）
「誰が Cowork を使えるか」と「いくらまで使えるか」をまとめて決める設定です。予算だけでなく、利用できる人を決める鍵にもなっています[2]。
プロンプトインジェクション
Web ページやメールに紛れ込ませた「隠れた指示」で、AI を本来の目的からそらす攻撃です。
DLP
情報漏えい対策（Data Loss Prevention）のルールです。Microsoft Purview で設定します。
条件付きアクセス
「どの端末・どの場所からならサインインしてよいか」を決める Microsoft Entra ID の仕組みです。

どんな機能？ 頼んでから終わるまで

Cowork は、社員のパソコンに入っている Edge の中で、見えないタブを開いて作業します。クラウド上の別のブラウザーではなく、本人の Edge を使うのがポイントです[1]。

  1. 頼む

    Edge で開いた Web 版 Cowork（copilot.cloud.microsoft.com）に「Concur で経費精算を出して」「この日程の航空券を探して」のように頼みます。ブラウザーを使うかどうかは Cowork が判断するので、特別なコマンドは要りません[1]。Edge のサイドペインや新しいタブページからも使えます[3]。

  2. 見えないタブで作業する

    Cowork が本人の Edge に隠しタブを開き、そこで操作します。本人はチャット画面のまま、進み具合を確認できます。「Switch to tab」を押せば、いつでもタブを開いて様子を見られます[1]。

    Opening ConcurFilling expense detailsSubmitting form

  3. 大事なところで止まる・人に戻す

    住所や確認コードなどが必要なときは、チャットで質問してきます。個人情報を送るなど影響の大きい操作の前には承認カードが出て、「Approve」か「Reject」を選びます。パスワード・MFA・CAPTCHA・アカウントのロック解除・パスワードリセットが出てきたら、タブを表示して本人にバトンタッチします[1]。支払いの確定も本人に戻す対象です[6][13]。

  4. 結果を報告する

    終わったらチャットで結果を報告します。本人がバトンタッチされた手順を完了できなかった場合は、作業を止めて「どこまでできなかったか」を伝えます。タブを閉じる・スリープ・ネット切断で一時停止し、「continue」などと送ると再開します[1]。

押さえておきたい3つの事実
  • サインイン情報・Cookie・セッションは本人の Edge に残り、Cowork のサーバーには送られません[1]。
  • 初めて使うときに案内が出て、本人が「I understand」を押すとブラウザー利用が有効になります。この同意は Cowork ではなく、その端末の Edge に記録されます。断った場合、Cowork はブラウザーの手順を飛ばして、飛ばした手順を伝えます[1]。
  • Microsoft は、プロンプト・回答・ファイルはテナントの中にとどまり、モデルの学習には使われないと説明しています（管理者が外部のモデルを有効にした場合は、その処理者の条件で処理されます）[13][6]。

オンにしたときのリスク

公式の歯止めがあっても残るリスクを6つに分けました。公式 は Microsoft の資料に書いてあること、考察 は資料から筆者が推し量ったこと、記載なし は公式資料で確認できなかったことです。

R1

Web ページの「隠れた指示」に操られる（プロンプトインジェクション）

起きうること
考察 Cowork は作業中に社外サイトの文章も読みます。そこに「この内容を別の宛先に送れ」のような指示が紛れていると、AI が目的からそれる可能性があります。ブラウザー利用では本人のサインイン状態で操作できるので、チャットだけの AI より影響が大きくなりがちです。
公式の歯止め
公式 影響の大きい操作は承認カードで止まり、中〜高リスクの操作はリスク表示つきで承認が必須です[6]。本人の権限を超えることはありません[1]。Purview の内部リスク管理には、プロンプトインジェクション攻撃を対象にした「Risky AI usage」ポリシーテンプレートがあります[7]。
わからないこと
記載なし Cowork のブラウザー利用ページと「責任ある AI」の FAQ には、プロンプトインジェクションへの具体的な対策の記載がありません[1][6]。
管理者の打ち手
URL の許可リストで行き先を業務サイトに絞る[9]／承認カードの中身を読む習慣を利用者に伝える／Risky AI usage テンプレートの導入を検討する[7]
R2

「本人と同じ権限」＝本人ができることは全部できる

起きうること
考察 管理画面や経理・人事システムに強い権限を持つ人ほど、読み違いや乗っ取りが起きたときに影響が広がります。
公式の歯止め
公式 エージェントのアクセス範囲は「本人が手で操作するときとまったく同じで、多くも少なくもない」とされています[1]。シングルサインオン・条件付きアクセス・DLP などは回避しません。サイトの利用規約も回避せず、人とやり取りするときに本人になりすますこともしません[6]。
管理者の打ち手
URL のブロックリストで、管理コンソールや確定・送金系の画面を外す[10]／強い権限を持つアカウントは最初のパイロット対象から外す考察
R3

指示の読み違い・途中で止まる

公式の説明
公式 あいまいな指示や広すぎる指示を読み違えて、意図と違う操作をすることがあります。依存関係の多い複雑な作業は、思った通りに完了しないことがあります。法務書類・医療判断・承認手続きを飛ばす金融取引のように、人の確認なしで正確さが求められる用途は想定外です[6]。
見落としやすい点
公式 承認ダイアログには「Don't ask again」があり、押すと同じ会話の中で似た操作の確認が省略されます[6]。考察 確認が続くと押したくなるボタンなので、使いどころを決めておくと安心です。
管理者の打ち手
「何を・誰に・どの形で」を具体的に書くよう利用者に伝える[6]／重要な業務は最後に人が確認する／「Don't ask again」の使い方を社内ルールに入れる
R4

コストが読みにくい

公式の説明
公式 Cowork は従量課金で、モデルの回答・ツールやスキルの呼び出し・画像生成と並んで、ブラウザータスクも組織の消費量に数えられます。管理者は Microsoft 365 管理センターで利用状況を確認し、ユーザー・グループ単位で上限を設定できます[2]。
管理者の打ち手
パイロットグループ用の支出ポリシーに上限を付ける／Cowork の利用状況レポートで消費を見る[2]
R5

端末まかせになる「設定のすき間」

公式の説明
公式 Edge のポリシー CopilotCoworkToolActionsEnabled を構成しないままだと、利用者が Edge の設定画面で自分でオン・オフできます。このポリシーは Edge だけでなく、Copilot デスクトップアプリに内蔵されたブラウザーでの操作にも効きます[4]。URL の許可・ブロックリストは Edge 158 以降で効く新しいポリシーで、以前の URL リスト用ポリシーは 158 で効かなくなりました[9][11]。
管理者の打ち手
ポリシーを「未構成」のままにせず、明示的に配る／Edge を 158 以上に更新する／古い BrowsingWithCopilot… 系ポリシーを新しい名前に置き換える[11][12]
R6

あとから追いにくい（記録の細かさ）

公式の説明
公式 ブラウザータスクは1件ずつ統合監査ログに記録され、「ユーザーがブラウザータスクを開始した」は代表的なイベントとして挙げられています[2][7]。Purview の DSPM for AI では、Cowork のやり取りは Activity explorer の「AI activities」タブに出ますが、「Apps and agents」ダッシュボードや AI observability には出ません[7]。
わからないこと
記載なし 監査レコードに、訪れた URL やページで行った操作の中身まで残るかは書かれていません[7]。
管理者の打ち手
パイロット中に実際の監査レコードを開いて、自社で追える範囲を確かめておく考察

守りは4層で考える

上の層ほど「広く・前もって」、下の層ほど「その場で・個別に」効きます。どれか1つに頼らず、重ねて使う前提で設計されています。

① 管理センター誰が使えるか

支出ポリシーで Cowork を使える人と上限を決め、「Browser use in Microsoft Copilot」でブラウザー利用を許すグループを決めます[2][5]。

② Edge ポリシーどの端末・どのサイトで

端末やプロファイルごとに操作を許すかどうか、どの URL なら操作してよいかを決めます[4][9][10]。

③ いまある守りそのまま引き継がれる

条件付きアクセス・Web フィルタリング・Edge の管理ポリシー・Purview DLP・監査ログ[1][7]。

④ その場の承認利用者が判断する

承認カード、リスク表示、サインイン・MFA・支払いのバトンタッチ[1][6]。

④は利用者の判断に頼る層です。①〜③で「そもそも行けない・できない」範囲を広げておくほど、④の負担が減ります。

  1. STEP 0

    準備する

    • Edge を 152.0.4191.53 以上にします。URL の許可・ブロックリストを使うなら 158 以上が必要です（Stable 158.0.4370.33 は 2026-11-19 公開）[1][11]。
    • 利用者は Cowork と同じ職場アカウントで Edge にサインインしておきます[1]。
    • パイロット用の Microsoft Entra セキュリティグループを作ります[2][5]。
  2. STEP 1

    Cowork を使える人と上限を決める

    従量課金を有効にしたうえで、支出ポリシーを作ります[2]。

    Copilot›Cost Management›Configuration›+ Add spending policy
    • 「Scope user and group」で Specific groups を選び、パイロットグループを指定
    • 「Select agents and services」で Cowork を選択

    支出ポリシーは予算であると同時に「誰が使えるか」の鍵です。上限を低くしても利用自体は止まりません。使えなくするには、Cowork を含むすべての支出ポリシーから外します。また、Agents › All Agents にある Cowork の項目をいじっても、誰が使えるかには影響しません[2]。

  3. STEP 2

    ブラウザー利用をオンにする

    Copilot›Settings›View All›Browser use in Microsoft Copilot
    • 「Allow browser access」で Allow Cowork to use the Microsoft Edge browser to perform tasks on behalf of users にチェックを入れます[1][5]。
    • 対象は No users／All users／Specific groups から選べます。最初は Specific groups でパイロットグループだけにします[5]。
    • 既定はオフです[1][5]。

    このパネルは 2026年10月に「Cowork settings」から「Browser use in Microsoft Copilot」へ名前が変わりました。機能と既存の設定はそのままです[8]。Microsoft Learn の本文は旧名の「Cowork settings」のままなので、画面と見比べるときは注意してください[1]。

  4. STEP 3

    Edge のポリシーを配る

    グループポリシー（MSEdge.admx の「Administrative Templates/Microsoft Edge」）や Mac の構成プロファイル、Intune などの端末管理で配ります[4][9]。どれも Windows と macOS 向けで、Android・iOS は対象外です。

    • 許可・ブロックリストは「より具体的に書いたルール」が勝ち、同じ具体さなら許可が勝ちます。書き方は URLAllowlist／URLBlocklist と同じで、使われるのは先頭から 1,500 件までです[9][10]。
    • contoso.com と書くとサブドメインも含み、.contoso.com と書くとそのホストだけになります。*.contoso.com の形は一致しません[9]。
    • リストを作っただけではブラウザー利用はオンになりません。STEP 2 とセットです[9][10]。
    • Cowork の管理ページは「許可リスト・ブロックリスト・閲覧のみのポリシーを尊重する」と書いています[2]。考察 Edge 側でこれに当たるのが上の2つと考えられますが、ポリシーのページ自体には Cowork の名前は出てきません。「閲覧のみ」に当たるポリシー名は確認できませんでした未確認。
  5. STEP 4

    いまある守りが効いているか確かめる

    条件付きアクセス・Web フィルタリング・Edge の管理ポリシー・Purview DLP は、ブラウザータスクにもそのまま引き継がれます[1][2]。パイロット利用者の端末で、ふだん禁止しているサイトや操作が Cowork からも止まることを確認しておくと安心です。DLP で止まったときは、Cowork がどの手順が止まったかを説明し、手作業のやり方を案内します[1]。

  6. STEP 5

    記録とコンプライアンス（Microsoft Purview）

    • 監査：プロンプトと回答、ブラウザータスクの開始などが統合監査ログに残ります[7]。
    • 内部リスク管理：「Risky AI usage」テンプレートでプロンプトインジェクション攻撃や保護された情報へのアクセスを検知対象にできます[7]。
    • 電子情報開示（eDiscovery）：会話の記録、Cowork が作ったファイル、スケジュールしたプロンプト、アップロードしたファイルが対象です[7]。
    • 保持：保持ポリシーは「Microsoft Copilot Experiences」を使います[7]。
  7. STEP 6

    小さく試して広げる

    メッセージセンターでも、まず小さなパイロットグループで評価してから広げることが推奨されています[5]。必要なら Copilot › Settings で Anthropic などのモデルを無効にできます。モデルを止めても、Cowork 自体が使えなくなるわけではありません[2]。

すぐ全社でオンにしない場合の現実解

A. 限定パイロットで始める

難易度：中追加コスト：ブラウザータスク分の従量課金

特定グループ（STEP 1・2）＋ URL 許可リスト（STEP 3）＋ 支出上限の3点セットで、行き先と予算を絞って試します。Edge ポリシーの配布が必要な分、少し手間がかかります[2][5][9]。

B. ブラウザー利用はオフのまま Cowork を使う

難易度：低追加コスト：Cowork 自体の従量課金のみ

ブラウザー利用をオンにしなくても、Cowork は Microsoft 365 の中の作業を進め、ブラウザーが必要な手順は飛ばしてその旨を伝えます。端末側で確実に止めたいなら CopilotCoworkToolActionsEnabled を「無効」で配ります[1][4]。

説明するときに外せない注意点

  • 同じ機能に名前が4つあります発表での名前「Cowork in Edge for Business」[3]、Cowork 管理ページでの呼び名「Cowork Browsing」[2]、管理センターのパネル名「Browser use in Microsoft Copilot」[8]、設定項目名「Allow browser access」[1]。資料を読むときに混乱しやすいところです。
  • 使えるのは「Edge で開いた Web 版 Cowork」だけデスクトップアプリ・モバイル・ほかのブラウザー・InPrivate・ゲストプロファイルでは動きません[1]。
  • GA でも既定はオフ管理者が有効にするまで使えません。提供状況はテナントや時期で変わることがあります[1][5]。
  • 米国政府向け（GCC）は別ルール既定オフの「Local Browsing Allowed」ポリシーで管理し、すべての操作に明示的な承認が必要です[1]。
  • 外部のモデルを使う場合管理者が Anthropic・OpenAI などのモデルを有効にすると、プロンプトはそれぞれの処理者の条件で処理されます。不要なら Copilot の設定で無効にできます[6][2]。
  • 今回確認できなかったことMicrosoft Edge 公式ブログの Ignite 2026 記事は、今回の調査環境から開けませんでした。スキルレコーダーとエージェント専用 ID の詳細は第三者報道の検索結果でしか確認できていないので、案内する前に公式発表で確かめてください[14][15]。
