SharePoint の「HTML ページ」で
事例共有ページを作る

SharePoint に、HTML ファイルをそのまま「ページ」として公開できる新機能「HTML ページ」が届き始めています[1][3]。この記事では、まず公式情報をもとに提供状況・できること・できないことを整理し、そのうえで「投稿」と「閲覧」を一体化した AI 活用事例の共有ページの設計案をまとめます。

結論

HTML ページは「見せる」のは得意、「受け付ける」のは苦手です。だから事例共有は、投稿はフォーム → リストに貯める → HTML ページで見せる、と役割を分けるのが理想です。

  1. HTML ページは、ページの中の「安全な箱」で動くため、JavaScript での絞り込みや検索、SharePoint リストのデータ表示はできますが、ページの中からファイルをアップロードしたり、リストに書き込んだりはできません[1][2]。
  2. 投稿の中身は PPTX や HTML ではなくフォームの入力項目にするのがおすすめです。全部の事例が同じ形でそろい、部署やツールで絞り込めて、集計もできます。PPTX は「添付してもよい」くらいの位置づけにします考察。
  3. ただし HTML ページはスマホアプリで見られない・コメントやいいねがないため、告知や盛り上げは Teams やふつうのモダンページと組み合わせます[1]。

先に押さえておきたい言葉

HTML ページ
HTML ファイル（Web ページの元になるファイル）を、SharePoint の「ページ」として公開できる新しい種類のページです。これまでのページ（モダンページ、拡張子 .aspx）と並んで使えます[3]。
サイトのページ
（Site Pages）
SharePoint サイトのページが保存される場所（ライブラリ）です。HTML ページもここに保存されます[1]。
サンドボックス
ページの中に用意された「安全な箱」です。HTML はこの箱の中だけで動き、SharePoint のメニューやほかのデータに勝手に手を出せません[1]。
ライブデータ
SharePoint リスト・Excel・CSV の中身を、ページを開いたり更新したりしたときに最新の状態で表示する仕組みです[2]。
CDN
インターネット上で公開されている部品（グラフを描くプログラムなど）の配布元です。HTML ページでは、Microsoft が用意したもの以外は読み込めません[1]。
SharePoint リスト
Excel の表のように、行と列でデータを貯められる SharePoint の機能です。今回の設計案では「事例の置き場」にします。

管理まわり

最初からオン。止めるのはサイトごと

HTML ページは既定で使える状態です。サイトの所有者が、次の場所で「HTML ファイルを許可」をオフにすると、そのサイトでは使えなくなります。普通のドキュメントライブラリにある HTML ファイルには影響しません[1]。

サイトのページ→ファイルの種類→HTML ファイルを許可

テナント全体でまとめてオフにすることはできません[1][2]。なお、設定がオフでも Copilot が HTML ページを作れてしまう事象を調査中と、Microsoft の担当者がコメントしています[2]。

外部へのリンクを許可する

SharePoint の外のサイト（たとえば Microsoft Forms）へリンクするには、サイト管理者が許可リストにドメインを追加します。許可されていないと「組織がこのサイトへのアクセスを許可していないため、このリンクを開けません」という表示になります[1]。

設定→サイト情報→すべてのサイト設定を表示→HTML フィールドのセキュリティ

PowerShell で確認する

サイトでこの機能が有効かは、PnP PowerShell の Get-PnPFeature で「HtmlPages」という機能を確認できます（機能 ID は公式記事に記載）[1]。

事例共有ページの設計案 考察

ここからは、上の仕様をふまえた提案です。

事例共有がうまくいかない理由は、だいたい次の2つです。設計は、この2つをつぶすことに集中します。

① 投稿がめんどくさい資料づくりに30分かかると、誰も出さなくなります。→ 投稿は5分で終わるようにする
② 読みたい事例が見つからないファイルが並んでいるだけだと、探す気になりません。→ 部署やツールで絞り込めるようにする

投稿の受け付け方は2択 考察

まずはこちらかんたん追加費用なし

A. リストの「新規」フォームをそのまま使う

  • リストを作るだけで、入力画面が自動でできます
  • 添付ファイルも付けられます
  • 同じ SharePoint の中なので、HTML ページからリンクするときに許可の設定がいりません[1]
慣れてきたらPower Automate が必要

B. Microsoft Forms ＋ Power Automate

  • 入力画面がとっつきやすく、ファイルアップロードの質問も使えます
  • Power Automate で回答をリストに登録し、Teams に「新着事例」を通知することもできます
  • Forms は SharePoint の外なので、HTML ページからリンクするにはサイト管理者がドメインを許可する必要があります[1]

完成イメージ（さわれる見本）

HTML ページの中の JavaScript でできる「絞り込み・検索・集計」を、小さく再現した見本です。データは架空です。実際のページでは、ここに SharePoint リストのデータが入ります。

気をつけたい落とし穴

  • スマホで見られないSharePoint・Teams のスマホアプリでは表示できません[1]。スマホで見る人が多い職場では、新着事例の告知をモダンページのニュースや Teams で行い、パソコンで HTML ページを開いてもらう流れにします。
  • いいね・コメントがないHTML ページには反応を返す仕組みがありません[1]。盛り上げは Teams のチャネルに任せ、ページからチャネルへリンクを張ります。
  • 「公開だけ表示」は見せ方の話見る人の権限ごとにデータが出し分けられるかは公式に記載がありません 未確認。表に出したくない情報は、そもそもリストに書かない運用にしておくと安心です。
  • いま展開中の機能一般提供の展開が続いている最中なので、仕様や画面が変わる可能性があります[2][3]。
  • 手元の HTML をそのままアップロードするとき外部の CDN から読み込む部品は動きません[1]。Google Fonts などの外部フォントも効かない可能性があります 未確認。その場合もフォントが標準のものになるだけで、文章は読めます。

進め方 考察

最初から完璧を目指すより、「まず5件集まる状態」を早く作るのが成功の近道です。

  1. 確認する 目安 30分

    HTML ページがテナントに来ているか、Copilot ライセンスがあるか、スマホで見る人がどれくらいいるかを確認します。

  2. リストと入口をつくる 目安 半日

    リストを作り、ふつうのモダンページにリスト（カード表示）と「投稿する」ボタンを置きます。HTML ページがまだ来ていなくても、これだけで運用を始められます。

  3. HTML のギャラリーに差し替える 目安 1日

    Copilot で HTML のギャラリーページを作り、入口をそちらに切り替えます。

  4. いい事例を記事にする 随時

    事務局がいい事例を選び、添付の PPTX を Copilot に渡して、1件1ページの HTML 記事にします。

  5. エージェントで探せるようにする お好みで

    事例リストを知識源にした SharePoint エージェントで、「この業務に使える事例はある？」に答えられるようにします。

HTML ページが使えないときの代わり 考察

難易度：低追加費用なしスマホ OK

モダンページ＋リスト Web パーツ

ふつうのモダンページにリストを置き、ギャラリー（カード）表示にします。絞り込みはリストのビューで行います。コメントやニュース配信も使えます。見た目の自由度は HTML ページより低くなります。

難易度：低追加費用なしPPTX 中心なら

モダンページ＋「強調表示されたコンテンツ」

PPTX や PDF を置いたドキュメントライブラリを、サムネイルつきのカードで並べる Web パーツです。ファイル中心で運用したい場合に向きますが、部署やツールでの絞り込みはファイルに列を足す必要があります。
