HOW IT WORKS

全体の流れ

事例集づくりは、Copilot が中身を書き、事例集メーカーが見た目を作り、人が確かめる、の分担で進めます。

1件の事例が冊子になるまで

  1. 人スライドを渡す発表スライド（pptx）と、この設計書
  2. COPILOT原稿を書く編集ルールに従って「事例テキスト」を出力
  3. 人確かめる「確認してほしいこと」を読んで直す
  4. 事例集メーカーページを組む貼るだけで、レベル順に並ぶ
  5. 人PDF にするチェックが通ったら保存して配る

なぜ、この分担にするの？

  • COPILOT ＝ 編集者中身だけを書くスライドを読んで要点をまとめ、レベルを決め、個人情報を外すのが得意です。見た目は作らせないので、55件でもページの形がそろいます。
  • 事例集メーカー ＝ 印刷所見た目を自動で作る表紙・目次・さくいん・章扉・ページ番号まで自動。長すぎる事例や、名前のような言葉も見つけて知らせます。
  • 人 ＝ 編集長最後に確かめる事実と数字が合っているか、載せてよい内容かを確かめます。発表者に原稿を見てもらうと、さらに安心です。

準備するもの

発表スライド事例ごとの pptx ファイル。1ファイルに複数の事例があっても大丈夫です。
この設計書Copilot に渡します（方法は次のページ）。
事例集メーカー上の URL を Edge か Chrome で開き、「名前を付けて保存」でパソコンに保存しておくと、いつでも使えます。
作業の目安1件あたり、Copilot への依頼が1回と、確認が数分。55件なら、数日に分けて進めると無理がありません。

HOW TO ASK

Copilot への頼み方

頼み方は2つあります。55件をまとめて進めるなら、方法B（専用のエージェントを作る）がおすすめです。毎回この設計書を添付しなくてよく、出力の形もそろいやすくなります。

方法A　Copilot Chat で頼む手軽

  1. Copilot Chat を開き、この設計書 PDF と発表スライドを添付する
  2. 下の文を貼って送る
  3. 出力されたコードブロックをコピーして、事例集メーカーに貼る

添付の「Copilot 活用事例集 設計書」の編集ルール（p.04〜06）に従って、添付の発表スライドから事例テキストを作ってください。

ナレッジこの設計書 PDF を追加します（見本や表記のルールを参照させるため）。

使うときは、チャットに発表スライドを添付して「このスライドから事例テキストを作って」と送ります。

うまく進めるコツ

  • 1回に1件ずつ頼みます。まとめて頼むと、事例どうしの内容が混ざることがあります。
  • 10件ほど進んだら、新しい会話を始めます。前の事例の言い回しが移りにくくなります。
  • 出力のあとの「確認してほしいこと」は必ず読みます。推測で書いた点や、伏せた情報が書かれています。
  • スライドの文字だけでは足りないときは、発表のメモや、話した内容の要点を一緒に渡します。
  • 表紙と「はじめに」「おわりに」の文は、「冊子情報を書いて」と頼み、会の目的や様子を伝えると作ってくれます。
  • 事例集メーカーに貼る前に、テキストを保存しておくと、あとから直すときに安心です。
添付できるファイルの種類や、エージェントの共有範囲は、会社の設定によって変わります。添付できないときは、スライドを OneDrive に置いて、チャットで「/」からファイルを指定してください。

EDITING RULES 1/3

Copilot への編集ルール

Copilot へ：このページから p.06 までが、あなたが従うルールです。発表スライドから事例テキストを書くときは、必ずこのルールと書式に従ってください。

役割

あなたは、社内の Copilot 事例共有会で発表されたスライド（PowerPoint）を読み、事例集に載せる原稿「事例テキスト」を書く編集者です。読み手は、Copilot を使い始めたばかりの社員です。

作業の流れ

  1. 渡されたスライドを最後まで読み、「何に困っていたか」「何を使って、どう作ったか」「どう変わったか」をつかむ。
  2. 「個人情報・社外秘のルール」に従って、載せてはいけない情報を外す。
  3. 「レベルの決め方」で、レベルを1つ決める。
  4. 「事例テキストの書式」のとおりに、1件を1つのコードブロックで出力する。
  5. コードブロックの後に「確認してほしいこと」を箇条書きで書く（スライドから読み取れず推測した点、伏せた情報、判断に迷った点）。なければ「なし」と書く。
  • 1つのスライドに事例が複数あるときは、事例ごとにコードブロックを分ける。
  • ほかの会話や、前に出力した事例の内容を混ぜない。

レベルの決め方

次の順に判定する。迷ったら低いほうにする。

  • Q1：エージェントもフローも作らず、その場で Copilot に頼む使い方か？ → はい：初級
  • Q2：自動で動く（メールの受信や決まった時刻などをきっかけに動く）、または、ほかのシステムへの登録・送信・更新までする（Power Automate のフロー、承認、コネクタなど）か？ → はい：上級／いいえ：中級

目安

  • 初級（使う）：Copilot Chat、Word・Excel・PowerPoint・Outlook・Teams の Copilot を、その場で使う。
  • 中級（作る）：エージェント ビルダーや Copilot Studio で、指示と資料をセットしたエージェントを作る。よく使う指示文をテンプレートにしてチームで使い回すのも中級。
  • 上級（つなぐ）：Power Automate などと連携して、申請・承認・通知などの手続きや自動化まで任せる。

EDITING RULES 2/3

Copilot への編集ルール（つづき）

ラベルの選び方

  • 業務の種類（1つ）：文書・資料づくり／メール・連絡／会議／調べもの・情報整理／データ集計・分析／問い合わせ対応／申請・手続き／その他
  • まねしやすさ（1つ）：今日からできる（準備なしで試せる）／準備がいる（資料をそろえる・エージェントを作るなど）／管理者に相談（Power Automate の接続、共有範囲の設定など、管理者の許可がいる）
  • 使ったツール（最大4つ、「、」区切り）：Copilot Chat／Word の Copilot／Excel の Copilot／PowerPoint の Copilot／Outlook の Copilot／Teams の Copilot／エージェント ビルダー／Copilot Studio／Power Automate／SharePoint／Forms。この表記にそろえる。ほかの製品はスライドの表記のまま書く。

個人情報・社外秘のルール（必ず守る）

  • 人の名前は書かない（発表者、同僚、上司、お客さま）。「担当者」「チームのメンバー」などに言いかえる。
  • 部署名は書く。発表者の所属部署を、スライドの表記のまま「部署」に入れる。わからなければ「（部署名を確認）」と書く。
  • メールアドレス、電話番号、社員番号、アカウント名、URL は書かない。
  • お客さま・取引先の名前、案件名、金額・売上などの数字は書かない。「あるお客さま」「○○」に置きかえる。
  • 社内システムの固有の名前は、一般的な呼び方にする（例：「勤怠システム」「申請システム」）。
  • 画面のスクリーンショットに写っている名前やデータは使わない。
  • 人事評価や、個人の成績にかかわる内容は書かない。

書き方のルール

  • ですます調。やさしい言葉で書く。専門用語を使うときは、短く言いかえをそえる。
  • スライドに書かれていない事実や数字を作らない。
  • 効果の数字は、スライドにあるものだけを書き、「（発表者の実感）」「（発表資料より）」のように出どころをそえる。数字がなければ、変化を言葉で書く。
  • 指示文は、スライドに載っている実物をそのまま写す（人や会社の名前は○○にする）。スライドに無いときは、まねしやすい例を書き、先頭に「【例】」とつける。
  • 項目ごとの文字数を守る（書式の（ ）内）。長いときは、削ってから出力する。

見本：スライドから事例テキストへ

架空の発表スライドを、編集ルールに従って事例テキストにした見本です。人の名前を外し、スライドにない数字は書いていません。

入力発表スライドの内容（架空）

総務部　規程案内エージェントを作ってみた

  • 発表：総務部 ○○
  • 出張・経費の問い合わせが毎日のように来る
  • 毎回、規程を探して条文を伝えていた

スライド 1〜2

作り方

  • 規程を SharePoint の1フォルダーに集めた
  • エージェント ビルダーで作成、ナレッジに規程フォルダー
  • 指示：規程だけで答える／条番号をそえる／判断は窓口へ
  • 部内で1週間試して公開

スライド 3〜4

結果・反省

  • よくある問い合わせが目に見えて減った
  • 回答の根拠がそろった
  • 表の中のルールを読み落とす → 表を文章で説明した資料を追加
  • 古い版は外した

スライド 5

出力事例テキスト

=== 事例 ===
レベル: 中級
タイトル: 「規程のどこに書いてある？」に答えるエージェント
部署: 総務部
業務の種類: 問い合わせ対応
まねしやすさ: 準備がいる
使ったツール: エージェント ビルダー、SharePoint
ひとこと: 規程集を読み込ませたエージェントが、根拠の場所をそえて答えてくれます。
これまで: 出張や経費のルールについて、同じような問い合わせが毎日のように届いていました。答えるたびに規程を探して、該当箇所を伝えていました。
これから: 規程を読み込ませたエージェントを部内に共有。よくある質問はエージェントが答え、担当者は判断が必要な相談に時間を使えるようになりました。
しくみ:
- 社員が質問する
- エージェントが規程を探す
- 根拠をそえて答える
- 判断がいる相談は窓口へ
やったこと:
- 規程のファイルを SharePoint の1つのフォルダーにまとめた
- エージェント ビルダーで、役割と答え方を日本語で説明した
- ナレッジ（参考にする資料）に、規程のフォルダーを追加した
- 部内で1週間試してもらい、答え方を直してから公開した
指示文:
あなたは総務部の規程案内係です。社員からの質問に、ナレッジにある規程だけをもとに答えてください。答えには、根拠となる規程の名前と条番号をそえてください。規程に書かれていないことや、判断が必要な相談には答えず、総務部の窓口に相談するよう案内してください。
工夫:
- 「規程に無いことは答えない」と書いたことで、あいまいな回答が減りました
- 古い版の規程はフォルダーから外し、最新版だけにしました
つまずき:
- 表の中のルールを読み落とすことがあり、表の内容を文章で説明した資料を足しました
効果:
- よくある問い合わせへの対応が目に見えて減った
- 回答の根拠がそろい、案内のばらつきが減った
まねするヒント: 問い合わせの多い資料がある部署にぴったりです。まずは資料を1か所にまとめるところから始めましょう。

MAKER & CHECK

事例集メーカーの使い方と、配る前のチェック

使い方

  1. 事例集メーカー（HTML）を Edge か Chrome で開きます。最初は見本が入っているので、「見本を消す」を押します。
  2. Copilot が出力した「=== 冊子情報 ===」と「=== 事例 ===」のかたまりを、枠に続けて貼ります。貼った順に、レベルごとに並びます。
  3. 右の「チェック」を見ます。赤は直す必要があるもの、黄は確かめてほしいものです。押すと、そのページに移動します。
  4. 直すときは、枠の中の文字を直接書きかえます。プレビューにすぐ反映されます。
  5. 「テキストを保存」で、貼った内容を .txt に保存しておきます（次に「テキストを開く」で続きから作れます）。
  6. 「PDFにする」を押し、「PDF として保存」・余白「なし」・「背景のグラフィック」オンで保存します。
貼った文字は、そのパソコンのブラウザの中だけで使われ、どこにも送られません。入力内容はブラウザに自動で保存されますが、念のため .txt でも保存してください。

よくある質問

事例の順番を変えたい
枠の中で「=== 事例 ===」から「=== おわり ===」までを切り取って、入れたい位置に貼り直します。レベルが変わる場合は「レベル:」を書きかえます。
表紙のタイトルや発行者を変えたい
「=== 冊子情報 ===」の「タイトル:」「発行:」などを書きかえます。
「1ページに収まりません」と出る
その事例の長い項目（指示文・やったこと・これまで／これから）を短くします。文字数の目安は p.06 の書式にあります。

配る前のチェックリスト

  • 人の名前が入っていない　発表者・同僚・お客さま。チェックの黄色「名前かもしれない言葉」も確かめる
  • 部署名が正しい　「（部署名を確認）」が残っていない
  • 数字に出どころがある　スライドにない数字が入っていない
  • 「指示文の例」を確かめた　事務局で用意した例として、内容に問題がない
  • チェックの赤が0件　すべての事例が1ページに収まっている
  • 発表者に原稿を見てもらった　載せてよい内容か、表現にまちがいがないか
