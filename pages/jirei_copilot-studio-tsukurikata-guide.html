HOW TO USE

このガイドの使い方

活用事例集の「つくり方」を、もう少しくわしくした手順書です。1つの事例を1ページにまとめ、上から順に進めると、試作から公開までたどれます。

ページの見方

  1. 1準備するもの・作る前に確認
  2. 2作る手順
  3. 3指示の例（コピーして使えます）
  4. 4テストの質問
  5. 5うまくいかないとき

画面の表記

Add knowledge のような囲みは、画面のボタンや項目の名前です。英語の画面の表記にそろえています。日本語の画面では、表記がちがうことがあります。

作る前の共通チェック

  • 作る場所に入れるか

    Copilot Studio は copilotstudio.microsoft.com にサインインし、作業用の環境を選びます。エージェント ビルダーは Microsoft 365 Copilot の New agent から始めます。

  • 載せる資料の公開範囲

    使う人は、資料の中身を聞き出せる前提で選びます。社外秘の資料や個人情報は載せません。

  • ライセンスと利用量

    使える機能や利用量（Copilot クレジット）の扱いは、契約や設定で変わります。わからないときは管理者に確かめます。

  • 共有と公開のルール

    組織全体に公開するときは、管理者の承認が必要なことがあります。まずは自分とチームで試します。

初級総務・人事

社内規程アシスタント

作る場所Copilot Studioスタンダード ハーネス

社内規程アシスタントの作り方

完成すると規程の質問に、資料名と条番号つきで答えるエージェントを作ります。 事例集 p.06

準備するもの

  • 規程のファイル（文字を選択できる Word・PDF）
  • 作業する Power Platform 環境
  • 資料にない質問の案内先（例：総務部の窓口）

作る前に確認

  • Copilot Studio にサインインして、作業用の環境を選べるか
  • 載せてよい資料か（使う人は中身を聞き出せる前提で選ぶ）

作る手順

  1. 作り始めるCopilot Studio の Home で New experience をオフにし、作りたいものを一文で入力して送ります
  2. 名前と指示を整えるOverview で名前を直し、下の「指示の例」を貼り付けて保存します
  3. 規程を入れるAdd knowledge から規程ファイルをアップロードし、どんな質問で読む資料かを説明に書いて Add to agent を押します。取り込みには数分かかります
  4. 資料の外は答えないようにするSettings の生成 AI の項目で、Use general knowledge と Web 検索をオフにします
  5. 試すTest your agent で下の「テストの質問」を聞きます。設定を変えたら、新しいセッションで試します
  6. Teams に出すPublish で公開し、Channels の Teams and Microsoft Copilot で Add channel を押して、自分の Teams に追加します
  7. ほかの人に広げる使う人に共有し、Availability options からリンクを配ります。組織全体には管理者の承認が要ります

指示の例

あなたは社内規程の問い合わせ窓口です。
・ナレッジの規程資料だけを根拠に答えてください。
・最後に、根拠の資料名と条番号を示してください。
・資料にないことは推測せず、「規程に記載がないため、総務部に確認してください」と答えてください。
・結論から、丁寧語で簡潔に答えてください。

○○ や部署名は、自分の職場に合わせて直します。

テストの質問

聞く質問こう答えれば OK
有給は何日前までに申請すればいい？就業規則から、条番号つきで答える
国内出張の日当はいくら？旅費規程から答える
来年の社員旅行はどこ？「記載がない」と窓口を案内する

うまくいかないとき

「分からない」ばかり返る取り込みが終わっていません。数分待ち、新しいテストセッションで聞き直します
資料にないことまで答える一般知識と Web 検索がオフになっているか確かめます
Teams で古い答えのままチャットで「start over」と送ると、最新の内容で会話をやり直せます

初級人事・受け入れ部署

入社・異動ガイド

作る場所エージェント ビルダーMicrosoft 365 Copilot

入社・異動ガイドの作り方

完成すると新しく来た人が Copilot Chat で、手続きや社内用語を聞けるエージェントを作ります。 事例集 p.07

準備するもの

  • 案内資料をまとめた SharePoint のサイト
  • 担当窓口の連絡先の一覧
  • 共有する相手（受け入れ部署・新しく来た人）

作る前に確認

  • Microsoft 365 Copilot に New agent が表示されるか
  • 共有する相手が、そのサイトを閲覧できるか（サイト管理者に確認）

作る手順

  1. 資料をまとめる入社手続き・用語集・システム一覧を、SharePoint の1つのサイトにまとめます。古い資料は外します
  2. 作り始めるMicrosoft 365 Copilot で New agent を選び、Skip to configure で設定画面を開きます。言葉で説明して作ることもできます
  3. 基本情報を入れるConfigure で名前（30文字まで）・説明・指示を入れます。指示は下の例を参考にします
  4. ナレッジを入れるKnowledge に、まとめた SharePoint のサイトを追加します
  5. 質問の例を出すStarter prompts に「経費精算のやり方は？」など、よくある質問を登録します
  6. 試すTry it で、下の「テストの質問」を聞きます。直したら、もう一度試します
  7. 作成して共有するCreate で作成し、Share で相手を Can chat として追加します。チャット用のリンクも配れます

指示の例

あなたは、新しく来た人のための案内役です。
・ナレッジにある社内の案内資料をもとに、やさしい言葉で答えてください。
・手続きを聞かれたら、手順を番号つきで示し、資料の場所も伝えてください。
・資料にない内容は推測せず、担当の窓口を案内してください。

○○ や部署名は、自分の職場に合わせて直します。

テストの質問

聞く質問こう答えれば OK
経費精算はどのシステムでやるの？システム名と、手順がのっている資料を示す
「稟議」ってなに？用語集をもとに、やさしく説明する
来月の歓迎会はいつ？資料にないため、窓口を案内する

うまくいかないとき

共有した人に答えが出ないその人がサイトを閲覧できるか確かめます。サイト全体の権限は自動で共有されないため、サイト管理者に付けてもらいます
直した内容が反映されない編集したあと、右上の Update を押します。反映まで数分かかります
Teams のチャットに追加できないエージェント ビルダーで作ったエージェントは、Teams のグループチャットや1対1のチャットでは使えません。Copilot Chat から使います

初級情報システム

ITヘルプデスク

作る場所Copilot Studioスタンダード ハーネス

ITヘルプデスクの作り方

完成するとよくある IT の問い合わせに、手順書をもとに番号つきで答えるエージェントを作ります。 事例集 p.08

準備するもの

  • 問い合わせ上位10件の手順書
  • 情報システム窓口の連絡先

作る前に確認

  • 手順書の画面や手順が最新か（更新日を見る）
  • 管理者向けの設定値など、一般の社員に見せない情報が入っていないか

作る手順

  1. 作り始める01 と同じく、Home で New experience をオフにし、作りたいものを一文で入力して送ります
  2. 指示を入れるOverview で、下の「指示の例」を貼り付けます。窓口の連絡先は自分の職場のものに直します
  3. 手順書を入れるAdd knowledge で手順書を追加します。SharePoint のフォルダーでも追加できます。説明に、対象のトラブルを書きます
  4. 資料の外は答えないようにする01 と同じく、一般知識と Web 検索をオフにします
  5. 最初のあいさつを変えるテストチャットのあいさつ文を選ぶと Conversation Start が開きます。「パスワード」「VPN」など聞ける内容の例を書いて保存します
  6. 質問の例を出すOverview の Suggested prompts に、よくある質問を10件まで登録します。Teams と Copilot で表示され、テストチャットには出ません
  7. 試して公開する下の「テストの質問」で試し、01 と同じ流れで Teams に出します

指示の例

あなたは社内 IT ヘルプデスクの一次窓口です。
・ナレッジにある手順書だけを根拠に、手順を番号つきで答えてください。
・パスワードなどの秘密の情報は、チャットに書かないよう案内してください。
・手順で解決しない場合や手順書にない内容は、情報システム窓口（連絡先：○○）を案内してください。

○○ や部署名は、自分の職場に合わせて直します。

テストの質問

聞く質問こう答えれば OK
VPN につながらない手順書の手順を、番号つきで示す
プリンターを追加したい手順と、参照した手順書名を示す
新しいPCがほしい手順書にないため、窓口を案内する

うまくいかないとき

Copilot であいさつが出ないMicrosoft 365 Copilot では Conversation Start が使えません。Suggested prompts で聞ける内容を伝えます
手順が古い手順書を新しくします。SharePoint に置いた手順書なら、更新が答えにも反映されます
解決しない問い合わせを記録したい受付票を作るツールを足します。くわしくは 07 の作り方を見てください

初級営業・企画

製品資料ナビ

作る場所エージェント ビルダーMicrosoft 365 Copilot

製品資料ナビの作り方

完成すると営業担当が、製品の特長や仕様を資料名つきで確かめられるエージェントを作ります。 事例集 p.09

準備するもの

  • 最新版の製品資料をまとめた SharePoint のフォルダー
  • 価格や契約についての問い合わせ先

作る前に確認

  • フォルダーに、古い版や社外に出せない資料が混ざっていないか
  • 営業チームが、そのフォルダーを閲覧できるか

作る手順

  1. 資料を整える最新版の製品資料を1つのフォルダーに集め、古い版は別の場所へ移します
  2. 作り始めるMicrosoft 365 Copilot で New agent を選び、「営業向けに、製品資料から特長や仕様を答えるエージェント」のように説明します
  3. 設定を確かめるConfigure で、できあがった名前・説明・指示を確かめ、下の「指示の例」を参考に直します
  4. ナレッジを入れるKnowledge に、製品資料のフォルダーを追加します
  5. 試すTry it で、下の「テストの質問」を聞きます。価格を聞いて、担当部署が案内されるかも確かめます
  6. 作成して共有するCreate で作成し、Share で営業チームを Can chat として追加します
  7. あとから直す資料や指示を変えたら、右上の Update で反映します

指示の例

あなたは営業担当のための製品資料ナビです。
・ナレッジにある製品資料だけを根拠に答え、回答の最後に資料名を示してください。
・価格、値引き、契約条件は答えず、「営業企画部に確認してください」と案内してください。
・比較を頼まれたら、表か3行の箇条書きでまとめてください。

○○ や部署名は、自分の職場に合わせて直します。

テストの質問

聞く質問こう答えれば OK
製品Aと製品Bのちがいを3行で教えて資料名つきで、3行にまとめる
製品Aの対応OSは？仕様書をもとに答える
製品Aはいくらまで値引きできる？答えずに、担当部署を案内する

うまくいかないとき

古い情報が出る古い版がフォルダーに残っていないか確かめます
共有した人に答えが出ない資料の閲覧権限を確かめます。共有できなかったファイルは、SharePoint で個別に権限を付けます
在庫など最新の数字も答えたいエージェント ビルダーでは外部とつなげません。Copilot Studio にコピーしてツールを足します（15 を参照）

初級製造・店舗などの現場

現場マニュアルナビ

作る場所Copilot Studioスタンダード ハーネス

現場マニュアルナビの作り方

完成すると現場の人がスマートフォンの Teams から、設備の手順と注意点を確かめられるエージェントを作ります。 事例集 p.10

準備するもの

  • 文字を選択できるマニュアル（PDF など）
  • 設備名・作業名の一覧
  • 現場で試してくれる人

作る前に確認

  • スキャンした画像だけの PDF ではないか（開いて文字を選べるか確かめる）
  • 現場の人が、スマートフォンの Teams を使えるか

作る手順

  1. 作り始める01 と同じく、Home で New experience をオフにし、作りたいものを一文で入力して送ります
  2. 指示を入れるOverview で、下の「指示の例」を貼り付けます。安全の注意を最初に伝えることが大切です
  3. マニュアルを入れるAdd knowledge でマニュアルを追加し、説明に設備名と作業名を書きます
  4. 資料の外は答えないようにする01 と同じく、一般知識と Web 検索をオフにします
  5. 試す下の「テストの質問」で、注意が最初に出るか、参照ページが示されるかを確かめます
  6. スマートフォンに届けるPublish で公開し、Teams のチャネルを追加します。スマートフォンの Teams ではインストール用のリンクが使えないため、Availability options の Show to my teammates and shared users で Teams のアプリストアに表示します
  7. 現場で育てる現場の人に使ってもらい、聞き方のくせに合わせて、指示や資料の説明を直します

指示の例

あなたは現場の作業手順を案内するアシスタントです。
・ナレッジにあるマニュアルだけを根拠に答えてください。
・安全に関わる注意がある場合は、必ず最初に【注意】として伝えてください。
・手順は番号つきで短く示し、最後にマニュアル名とページを示してください。
・マニュアルにない判断は推測せず、現場の責任者に確認するよう伝えてください。

○○ や部署名は、自分の職場に合わせて直します。

テストの質問

聞く質問こう答えれば OK
設備Xの日常点検の手順は？【注意】→ 手順 → 参照ページの順で答える
設備Xから異音がする該当する箇所を示す。なければ責任者への確認を案内する
設備Yの部品はどこで買える？マニュアルにないため、責任者を案内する

うまくいかないとき

答えが出ない・おかしな文字になる画像だけの PDF は読み取れないことがあります。元のデータを探すか、作り直します
スマートフォンで見つからないTeams のアプリストアに表示する設定（Show to my teammates and shared users）を確かめます
答えが長くて読みにくい指示に「3行以内で」など、答えの長さを書き足します

PDFで保存する

このあと開く印刷画面で、次のように選ぶと、配布用と同じ A4・8ページ の PDF になります。

  1. 送信先（プリンター）で「PDF に保存」を選びますMicrosoft Edge では「PDF として保存」です
  2. 用紙サイズは A4、倍率は 100%（既定のまま）にします
  3. 色がうすいときは、詳細設定の「背景のグラフィック」にチェックを入れます

Google Chrome または Microsoft Edge での利用がおすすめです。紙に印刷するときは、送信先でプリンターを選びます（両面印刷なら4枚です）。
