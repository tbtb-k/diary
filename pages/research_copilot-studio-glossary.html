Copilot Studio 講師用 用語集

作成日2026-10-03
対象Copilot Studio を教える講師・社内推進担当
収録優先度 高 15語／中 22語／低 16語、混同しやすいペア 13組
使い方と全体像 優先度 高 優先度 中 優先度 低 混同しやすいペア 根拠

最初に押さえるのは「優先度 高」の15語です。中でも「説明」と「生成オーケストレーション」の関係が分かっていると、質疑応答がぐっと楽になります。

今の Copilot Studio では、AI（生成オーケストレーション）が、トピック・ナレッジ・ツール・他のエージェントに付けられた「説明」を読んで、どれを使うかを自分で選びます[6]。「思った部品が使われない」という相談の多くは、この説明の書き方で解決します。

もう一つ大きな変化があります。2026年8月に「ハーネス」（エージェントを動かす実行エンジン）が3種類になりました[1][13]。新しい「GitHub Copilot ハーネス」で増えた用語（スキル、メモリ、ワークフローなど）も収録しています。名前は似ていますが、開発者向けサービスの GitHub Copilot とは別物です[1]。

質問は指示に沿って生成オーケストレーションが受け取り、各部品の「説明」を手がかりにトピック・ナレッジ・ツール・他のエージェントから必要なものを選んで回答をまとめます[6]。

高 初回講義で必ず説明する15語 HIGH PRIORITY

受講者が最初の1時間で必ず目にする用語です。NEW は2026年に登場・変更された用語です。

用語（英語）ひとことで言うと講師が押さえるポイント
エージェントAgent 質問に答えたり、作業を代わりにやったりするAIアシスタント。Copilot Studio で作るものの単位。 旧称は「コパイロット」「ボット」。古い記事は旧称で書かれているので注意。人と会話するものと、イベントをきっかけに自分で動くもの（自律エージェント）がある。一般的な説明
ハーネスNEWHarness エージェントを動かす実行エンジン。AIモデル（頭脳）と設定（マニュアル）の間に立ち、いつモデルを呼ぶか、どのツールを使うかを仕切る。 2026年8月から3種類。標準ハーネス（トピック中心で予測しやすい）、GitHub Copilot ハーネス（長く複雑な仕事を自分で計画。ファイル作成・スキル・メモリに対応）、Copilot チャット ハーネス（Microsoft 365 Copilot Chat の拡張）。作成後に別のハーネスへは移行できない。GitHub Copilot ハーネスは GitHub Copilot というサービスとは別物で、データはそちらに送られない。[1][2][3]
指示Instructions エージェントの役割、口調、やってよいこと・いけないことを文章で書いたもの。 最初に書く「業務マニュアル」。「引用を必ず付ける」と書くと根拠つきの回答が安定するなど、回答の質にも直結する。[3][9]
ナレッジKnowledge エージェントが回答の根拠にする情報源。公開 Web サイト、SharePoint、アップロードしたファイル、Dataverse、コネクタ経由の社内データなど。 「資料棚」。SharePoint などは、質問した人が見る権限のある内容だけが回答に使われる。Microsoft Learn の日本語訳では「知識」「サポート情報ソース」とも訳されているので混乱注意。[9]
トピックTopic 「この話題が来たらこの流れで対応する」という会話の台本。ノードを並べて作る。 毎回同じ手順で対応させたいときに使う（例：休暇申請の受付）。AI任せにしない部分。標準ハーネスの機能。[2][6]
トリガー フレーズTrigger phrases トピックを起動させるための例文（「休みを取りたい」「有給申請」など）。 クラシック オーケストレーションで使う。生成オーケストレーションでは、代わりにトピックの「説明」で選ばれる。[6]
説明Description トピック、ツール、ナレッジ、他のエージェントに付ける「これは何に使うか」の文章。 生成オーケストレーションでAIが「どれを使うか」を決める最重要の手がかり。名前は具体的に、説明は1〜2文で、できないことも書く。似た説明が並ぶと選択が不安定になる。[6][7]
ツールTools エージェントが外部システムで「行動」するための部品。メール送信、データ登録、天気の取得など。 旧称は「アクション」。中身はコネクタ、エージェント フロー、プロンプト、REST API、MCP、コンピューター操作など。1エージェントあたり最大128個だが、25〜30個以内が推奨。[7]
コネクタConnector Outlook、Teams、Salesforce など外部サービスとつなぐための既製の接続口（Power Platform 共通）。 既製のものが数千種類ある。自社システム用に自作するのがカスタム コネクタ。組織のデータ ポリシーで使えないものもある。[7]
MCP（モデル コンテキスト プロトコル）Model Context Protocol AIと外部のツールやデータをつなぐ業界共通の規格。MCP サーバーにつなぐと、そのサーバーが持つツールをまとめて使える。 「AI用のUSB-C」とたとえると伝わりやすい。Copilot Studio では「ツール」と「リソース」に対応し、「プロンプト」は未対応。生成オーケストレーションが必須。サーバー側でツールが増えると自動で反映される。[8]
生成オーケストレーションGenerative orchestration 質問に対して、AIがトピック・ナレッジ・ツール・他のエージェントから最適なものを選び、組み合わせて回答する仕組み。 新しいエージェントの既定。「営業時間を確認して、最寄りの店も探して」のような複数の依頼を一度に処理できる。足りない入力はAIが自動で質問してくれる。[6]
クラシック オーケストレーションClassic orchestration トリガー フレーズに一番近いトピックを1つ選んで動かす従来方式。該当がなければナレッジで回答する。 動きが読みやすいが柔軟性は低い。ツールはトピックの中からしか呼べない。「設定 > 生成AI > オーケストレーション」で切り替える。[6]
テスト（テスト パネル）Test pane / Activity map 作成画面で実際に話しかけて動作を確かめる場所。アクティビティ マップで、AIがどのトピックやツールを選んだかが見える。 デモで「AIの頭の中」を見せるのに最適。会話履歴の影響で、同じ質問でも答えが変わることがある。GitHub Copilot ハーネスでは「プレビュー」タブにあたる。[3][6]
公開Publish 作ったエージェントを利用者が使える状態にする操作。 編集しただけでは利用者側に反映されず、変更のたびに再公開が必要。試用版ライセンスでは公開できない。[12]
チャネルChannel エージェントを使ってもらう場所。Teams と Microsoft 365 Copilot、Web サイト、SharePoint など。 チャネルごとに表示できるものが違う（例：Teams では引用は最大20件）。[9]

中 ハンズオンで出てくる22語 MEDIUM PRIORITY

画面のどこにあるかを指しながら説明できれば十分です。「スキル」と「メモリ」は、GitHub Copilot ハーネスを扱う講義なら「高」に格上げしてください。

用語（英語）ひとことで言うと講師が押さえるポイント
会話を組み立てる部品
ノードNode トピックの中の1ステップ。メッセージ、質問、条件分岐、変数の設定、ツール呼び出しなど。 フローチャートの「箱」にあたる。「＋」ボタンで追加する。[7]
変数Variable 会話の中で情報を一時的に覚えておく入れ物。 有効範囲が3種類。トピック変数（そのトピック内だけ）、グローバル変数（会話全体）、システム変数（ユーザー名など自動で入るもの）。一般的な説明
エンティティEntity ユーザーの発言から取り出したい情報の型。日付、数値、都市名、メール アドレスなど。 準備済みのものと、自作（選択肢リスト、正規表現）がある。自作エンティティはツールやトピックの入力にはまだ使えず、質問ノードで使う。[6]
スロット フィリングSlot filling ユーザーが最初の一言で言った情報を拾い、該当する質問を飛ばす仕組み。 「明日の東京の天気」と言えば「どこの？」と聞き返さない。エンティティとセットで説明すると伝わりやすい。一般的な説明
システム トピックSystem topics 最初から入っている特別なトピック。会話の開始、フォールバック、会話のブースト、エスカレート、エラー時、会話のリセットなど。 「会話の開始」で最初の挨拶を変えるのが定番のハンズオン。生成オーケストレーションでは「会話のブースト」はナレッジ検索に使われない。[6][9]
生成型の回答（生成回答ノード）Generative answers ナレッジを検索して、AIが文章で回答をまとめる機能。トピックの中にノードとして置くこともできる。 トピックを全部作らなくても答えられるのが強み。特定の資料だけを検索させたいときにノードで使う。[9]
根拠のない応答を許可するAllow ungrounded responses ナレッジやツールを使わず、AIの一般知識だけで答えてよいかの設定。 オフにすると「資料にないことは答えない」に近づく。ただし引用が付かないと正しい答えも隠れることがある。「引用を必ず付ける」と指示に書くと安定する。[9]
アダプティブ カードAdaptive Cards ボタンや入力欄つきのカード型の表示。 申請フォームや結果一覧を見やすく出せる。Teams での見た目が強み。[7]
自動化とマルチエージェント
エージェント フローAgent flows 決まった手順を毎回同じように実行する自動化。Copilot Studio の中で作る。 標準ハーネスのフロー。AIの気まぐれが入らない（決定的）ので、承認や記録などの定型処理に向く。ツールとしてエージェントに追加できる。[5][7]
ワークフローNEWWorkflows GitHub Copilot ハーネスで動く新しい自動化。AIアクションや人の承認を組み込める。 トリガー（開始のきっかけ）＋アクション（やること）でできている。左メニューの「ワークフロー」から作る。アクションごとに容量を消費する。[11]
Power AutomatePower Automate Microsoft の業務自動化サービス。エージェント フローと同じ仕組みが土台にある。 受講者が既に使っていることが多いので、「知っているフローの仲間」と紹介すると入りやすい。一般的な説明
プロンプトPrompt 決まった指示文でAIに1回だけ仕事をさせるツール。要約、分類、文章作成など。 指示文・使うモデル・入力項目を決めて作る。「文章を渡すと決まった形で返してくれる部品」と説明する。[7]
子エージェントChild agent エージェントの中に作る軽量のサブエージェント。 ひとつのチームで管理し、単独で公開しないものに使う。「部署の中の担当者」のイメージ。[10]
接続されたエージェントConnected agent 別に作られた独立エージェントを呼び出して仕事を任せる仕組み。 別チームが管理する、単独でも公開する、複数のエージェントで使い回す、というときに使う。「他部署への依頼」のイメージ。選択肢が30〜40を超えたら分割を検討。[10]
トリガー（イベント トリガー）Event triggers 「メールが届いたら」「毎朝9時に」など、人が話しかけなくてもエージェントを動かすきっかけ。 これを使うと自律エージェントになる。トピックの「トリガー」と名前が似ているので区別して説明する。[6]
スキルNEWSkills 特定の仕事のやり方を Markdown（SKILL.md）でまとめた、使い回せる手順書パッケージ。 GitHub Copilot ハーネスの機能で、公開仕様「Agent Skills」に準拠。ツールは外部とつなぐもの、スキルはやり方を教えるもの。標準ハーネスの「Azure Bot Service スキル」とは別物。[4][7]
メモリNEWMemory 過去のやり取りを覚えておき、次の会話に生かす機能。 GitHub Copilot ハーネスの機能で、現在プレビュー。変数（その会話だけ）との違いを聞かれやすい。[3][13]
環境・認証・課金・分析
環境Environment エージェントやデータを入れておく「部屋」。Power Platform 共通の単位。 開発用・本番用で分けるのが基本。ハンズオン前に、受講者がどの環境を使うか決めておく。一般的な説明
DataverseDataverse Power Platform のデータ保管場所（データベース）。 エージェント自体もここに保存される。アップロードしたファイルもここに入る。ナレッジとしても使える。[9]
認証Authentication この人は誰かを確かめる仕組み。 エージェント全体の設定と、ツールごとの設定がある。ツールは「エンドユーザーの資格情報（使う人の権限）」か「作成者が指定した資格情報（作った人の権限）」を選ぶ。情報漏えいの質問はここに結びつく。[7]
Copilot クレジットCopilot Credits Copilot Studio の利用量を数える共通の単位。会話やツール実行ごとに消費する。 2025年9月1日に「メッセージ」から名称変更。月ごとに使い切りで繰り越しなし。Microsoft 365 Copilot ライセンス保有者が Teams や Copilot Chat で使う場合、一部の回答はカウントされない。料金の詳細は公式のライセンス ガイドで確認する。[12]
分析Analytics 公開後の利用状況（会話数、解決率、満足度など）を見る画面。 「作って終わりではなく育てるもの」と伝える場面で使う。GitHub Copilot ハーネスでは「モニター」タブにあたる。[3][9]

低 質問されたら答えられればよい16語 LOW PRIORITY

管理者向けの設定や、発展的な機能の用語です。概要を一言で言えて、「詳しくは管理者／公式ドキュメントで」と誘導できれば十分です。

用語（英語）ひとことで言うと講師が押さえるポイント
管理・運用
ソリューション／ALMSolutions / Application lifecycle management エージェントやフローをまとめて別の環境へ運ぶ「箱」と、開発→テスト→本番と進める運用の考え方。 「開発環境で作ったものを本番に移すには？」と聞かれたらこれ。[10]
データ ポリシー（DLP）Data policies / Data loss prevention 管理者が「このコネクタやツールは使用禁止」と決めるルール。 ハンズオンで「ツールが選べない」ときの主な原因。情報アイコンで理由を確認できる。[7]
マネージド環境Managed Environments 環境単位で共有制限などの管理機能を強化する Power Platform の仕組み。 企業のガバナンス担当が気にする用語。詳細は管理者向けドキュメントへ。一般的な説明
Power Platform 管理センターPower Platform admin center 環境、容量（クレジット）、ポリシーを管理する管理者向け画面。 受講者自身は触らないことが多い。「容量を確認したい」ときの行き先。[11][12]
従量課金制Pay-as-you-go 事前購入せず、使った分の Copilot クレジットを Azure サブスクリプションで月末に支払う方式。 他に、前払いのクレジット パックと1年分の事前購入プランがある。[12]
評価（テスト セット）Evaluation / Test sets 質問と期待する答えのセットをまとめて流し、品質を測る仕組み。 「指示を変えたら他の回答が壊れた」を防ぐために使う。GitHub Copilot ハーネスでは「評価」タブ。[3]
コンテンツ モデレーションContent moderation 有害な内容をどれだけ厳しく弾くかの設定。最小〜最高。 既定は「高」。厳しくするほど答える量が減る。エージェント、トピック、プロンプトの各レベルで設定できる。[9]
発展的な機能
コンピューター操作Computer use API がないシステムでも、画面を見てクリックや入力をして操作するツール。 「古い社内システムも動かせる？」と聞かれたらこれ。RPA の AI 版とたとえると伝わる。[7]
REST APIREST API 自社や外部の API を、コネクタを作らず直接ツールとして追加する方法。 開発部門との会話で出てくる。非エンジニア向けには「システム同士の窓口」と説明する。[7]
モデルの選択Model selection エージェントやプロンプトの頭脳になるAIモデルを選ぶこと。 モデルを変えると同じ設定でも結果が変わるので、変えたら再テスト。選べるモデルは頻繁に増えるので、講義では具体名を断言しない。[3][6]
Web 検索Web search Bing で公開 Web 全体を検索して回答に使う設定。 ナレッジに登録した特定サイトだけを検索するのとは別。社内専用エージェントではオフにすることも多い。[9]
テナント グラフ グラウンディングTenant graph grounding with semantic search Microsoft 365 の検索技術（セマンティック インデックス）で、SharePoint などの検索精度を上げる設定。 「SharePoint の資料をうまく拾ってくれない」ときの改善策。追加のクレジット消費があり、「Microsoft で認証」の設定が必要。[9]
Power FxPower Fx Excel の関数に似た書き方の数式言語。変数の加工や条件分岐に使う。 「Excel 関数が書ければ読める」と伝えると安心される。[7]
サンドボックスNEWSandbox GitHub Copilot ハーネスで、各タスクを安全に実行する隔離された作業スペース。 Word・Excel・PowerPoint・PDF の作成や計算はこの中で行われる。[1][13]
A2A プロトコルAgent2Agent protocol 異なる会社のエージェント同士が会話するための共通規格。 MCP が「AIと道具」、A2A が「AIとAI」をつなぐと整理すると分かりやすい。[10]
Microsoft FoundryMicrosoft Foundry 開発者向けのAIアプリ・エージェント開発基盤（旧 Azure AI Foundry）。 「プロ開発者はこちら、業務部門は Copilot Studio」という位置づけ。Foundry のエージェントを接続する機能はプレビュー。[10]

受講者が混同しやすい用語ペア 13 PAIRS

質問で一番多いのは「これとこれは何が違うの？」です。右端の列をそのまま言えるようにしておくと安心です。

ペア違い受講者への言い方
トピック と ナレッジトピックは決めた流れで対応する台本、ナレッジは答えを探すための資料。必ず同じ手順でやらせたいならトピック、資料から答えてほしいならナレッジ
指示 と 説明指示はエージェント全体の振る舞い、説明は部品ごとの用途。指示は本人へのマニュアル、説明は道具に貼るラベル
コネクタ と ツールコネクタは外部サービスとの接続口。その中の操作（メール送信など）をエージェントに持たせるとツールになる。コネクタはコンセント、ツールはそこに挿した家電
ツール と MCPMCP はツールのつなぎ方の一種。MCP サーバー1つで複数のツールがまとめて入る。MCP は道具箱ごとつなぐ共通規格。中の道具はサーバー側で増えても自動で使える
ツール と スキルツールは外部システムで行動する部品、スキルは仕事のやり方をまとめた手順書。ツールは手足、スキルはノウハウ
生成 と クラシック（オーケストレーション）生成は「説明」を読んでAIが部品を選び組み合わせる。クラシックは「トリガー フレーズ」と照合してトピックを1つ選ぶ。自分で考えるベテランか、マニュアル通りの新人か
標準ハーネス と GitHub Copilot ハーネス標準は作り手が経路を設計して予測どおりに動かす。GitHub Copilot はゴールを渡して、AIが自分で計画・復旧する。後者はクレジットと応答時間が増えやすい。短く決まった仕事は標準、長く複雑で資料作りまでやる仕事は GitHub Copilot
GitHub Copilot ハーネス と GitHub Copilot前者は Copilot Studio の実行基盤。技術の一部を共有するだけで、データが GitHub Copilot サービスに送られることはない。名前が似ているだけで、開発者向けツールを契約する必要はありません
エージェント フロー と ワークフローどちらも決まった手順の自動化。エージェント フローは標準ハーネス、ワークフローは GitHub Copilot ハーネス用。中身は同じ発想。どちらのエンジンで作るかの違い
子エージェント と 接続されたエージェント子は親の中だけで使う軽量版。接続は単独でも公開できる独立したエージェント。部署内の担当者か、他部署への依頼か
トピックのトリガー と イベント トリガートピックのトリガーは会話中にトピックを起動するもの。イベント トリガーは会話なしでエージェント自体を動かすもの。話しかけられて動くか、出来事で動くか
変数 と メモリ変数はその会話の間だけのメモ。メモリは会話をまたいで覚えておく機能（プレビュー）。付箋と日記帳
Copilot Studio と Agent BuilderAgent Builder は Microsoft 365 Copilot の中で手軽にエージェントを作る機能。ツール連携や公開先の自由度が高いのは Copilot Studio。一般的な説明自分やチーム用にさっと作るなら Agent Builder、業務システムとつなぐなら Copilot Studio
