AI活用事例Copilot Studio2026年10月9日／IT企業（Microsoft）・ウェブサイトの顧客対応

サイトの問い合わせ対応が変わりました。Microsoft の「Ask Microsoft」は人の対応が最大70%減

Microsoft.com では問い合わせが営業担当者に集中し、応答の待ち時間も長くなっていました。

Copilot Studio で「Ask Microsoft」を作り、領域ごとのサブエージェントを使い分ける形に改善しました。

人が対応するチャット件数は最大70%減、応答時間は最大61%短縮と公表されています（特定サイトのテスト結果）。

01こんな場面、ありませんか

お店で「ちょっと聞きたいだけ」なのに、担当者を呼ぶしかない。ウェブサイトでも、情報が多すぎて探せず、とりあえず問い合わせる人は少なくありません。

Microsoft.com は数千ページ規模で、毎日数百万人が製品や価格の情報を求めて訪れます。見つけにくいため、チャットで営業担当者に、営業以外の質問まで寄せられていました。さらにアクセスが増えると、エージェントの応答待ち時間が長くなり、顧客から指摘が出るようになりました。

02やってみたこと

Microsoft のウェブチームは、Copilot Studio（ノーコード・ローコードで AI エージェントを作れるツール）で「Ask Microsoft」というウェブ用エージェントを作りました。サイト各所に埋め込まれ、製品案内、技術サポート、サインアップの手伝いをします。

Azure の製品サイトのチームが試作して数週間で公開し、その後10の製品サイトへ週2サイトのペースで広げました。のちに、1体で全部を担当する形から、Azure・Microsoft 365・価格・トライアルなど領域ごとのサブエージェント（専門担当のエージェント）を、AI が選んで使い分ける形へ作り替えています。

  1. Copilot Studio で試作し、数週間で公開する。
  2. ほかの製品サイトへ、週2サイトのペースで広げる。
  3. AI が適切なサブエージェントを選ぶ構成に作り替える。
  4. フラグで旧版と新版を切り替え、A/B テストと段階的な展開をする。問題があれば旧版へ戻せる。
  5. 全エージェント横断のダッシュボードで、応答時間・エラー・利用状況・フィードバックを見る。

担当者が必要な場合は、ライブチャットへ引き継げます。価格ページのように長いページは Copilot Studio だけでは扱いにくく、Microsoft Foundry で作ったサブエージェントが補っています。

03どう変わったか

これまで

営業担当者に、営業以外の質問も含めて何でも問い合わせが来ていました。トラフィックの増加で応答も遅くなっていました。

いま

最大61%の応答時間の短縮（Microsoft 365 サイトのテスト）、人が対応するチャット件数の最大70%減が公表されています。Azure サイトのテストでは、製品トライアルの開始が16%増えました。

いずれも Microsoft が公表した数字です。「最大」とあるものは特定のサイトでのテスト結果で、すべてのサイトに当てはまるとは限りません。また、Ask Microsoft を使った顧客は、サインアップに進む可能性が10倍になったと公表されています。

04明日から試すには

  1. よくある問い合わせを集め、ウェブで自己解決できそうなものを選ぶ。
  2. Copilot Studio で小さなエージェントを作り、1つのページだけで試す。
  3. 応答時間と、人に引き継がれた件数を記録して、改善の材料にする。

準備物は、答えの元になる公開ページや FAQ です。お客様向けに公開する場合は、必要な権限や契約が変わるため、社内のルールを確認してください。

05つまずきやすいところ

お客様に見せる AI は、慎重に広げる必要があります

出典では、顧客が直接触れるツールは体験の質が特に重要だとして、段階的な展開が欠かせなかったとされています。会話の流れが固定されていると、複数の製品にまたがる質問に答えにくい点も課題でした。

社内で真似するときは、AI が間違える場合を想定し、人へ引き継ぐ道を残してください。答えの元にする文書は、最新で公開してよいものに限ります。

06おわりに

この事例の学びは、最初から完成形を目指さず、小さく出して計測し、旧版へ戻せる形で作り替えたことです。

自分の職場に置き換えると、社内ヘルプデスクや総務の窓口で、まず一部の質問だけをエージェントに任せ、答えられないものは人へ回す形から試せます。
