AI活用事例Agent Builder2026年10月2日／IT サービス業（HCLTech）・全社のエージェント作り

社員8万人超に声をかけ、約6週間でエージェントを使う人が3,056人から13,727人に増えました

HCLTech は、Microsoft 365 Copilot を配っても、多くの社員がエージェント（AI の専用アシスタント）を作る・使うところまで進まないという課題を抱えていました。

2026年5月中旬から6月末まで、8万人超の社員を招き、Agent Builder（Microsoft 365 Copilot に含まれる、コードを書かずにエージェントを作れる機能）を使った「Agent Buddy Program」を実施しました。

キャンペーン中に、エージェントを使っている社員は3,056人から13,727人へ、349%増えました。

01こんな場面、ありませんか

ライセンスは配った。でも、ふたを開けると一部の詳しい人しか使っていない。社内でAIを広げようとした人なら、一度は経験する場面ではないでしょうか。

Microsoft の記事は、この状況を「技術の準備はできているのに、広い範囲の利用が進まない」と整理しています。課題は技術よりも、気づきや自信、「自分の仕事に役立つ」という実感をどう作るか、という点にあるとしています。

02やってみたこと

Agent Builder は、日本語などの自然な言葉で「こんなエージェントがほしい」と伝えるだけで、エージェントを作れる機能です。HCLTech は、これを広めるための取り組みとして、説明会ではなく、一緒に作る「co-build（共同ビルド）」形式のセッションを開きました。

セッションは、事業部ごとの優先課題や実際の業務に合わせて設計されました。研究・分析、社内ナレッジの検索、計画・生産性、レポート作成、社員の学習、コミュニケーション、開発・品質保証といった場面が扱われました。

  1. 社員8万人超を対象に、キャンペーン（Agent Buddy Program）として声をかけました。
  2. 事業部ごとの課題に合わせた、手を動かすセッションを開きました。見るだけではなく、参加者が自分で作る形です。
  3. 参加者から、エージェントのアイデアが1,100件以上出ました。最も多かったのは「計画・生産性」の分野でした。
  4. セッションの後も、アイデアの共有や、より進んだ使い方の要望が続いたと記事は伝えています。

※ 4つの手順は、出典の説明を順に並べ直したものです。流れ図の「社内で共有・継続して使う」は、出典の「セッション後も参加者が使い方を共有した」という記述をまとめた表現です。

03どう変わったか

これまで

全社で使えるようになっていても、実際にエージェントを作った・使った人は一部に限られていました（記事は、使用中のユーザー3,056人という開始時点の数字を示しています）。

いま

エージェントを使う社員が13,727人（ライセンスありが8,722人、なしが5,005人）に増えました。HCLTech 全体で記録されたエージェントは36,286体で、うち27,375体は2026年上半期に作られました。社員が作ったエージェントは、使われたエージェントの73.9%を占めました。

数字は、Microsoft の記事が HCLTech の取り組みとして紹介している公表値です。業務の時間短縮や費用の削減などの効果は、記事では公表されていません。

04明日から試すには

  1. 自分の部署で、日々の仕事の中から「毎回同じことをしている作業」を1つ選びます。
  2. Microsoft 365 Copilot の Agent Builder を開き、その作業を言葉で説明して、エージェントを作ってみます。
  3. 同僚を2〜3人誘い、同じ画面を見ながら一緒に作る30分を設けます。記事も「見るより作る」ことを勧めています。

Agent Builder は Microsoft 365 Copilot に含まれる機能です。使えるかどうかは、ライセンスや管理者の設定で変わります。先に情報システム部門へ確認してください。

05つまずきやすいところ

セッション前にライセンスやアクセスを確認します

記事は、よくある詰まりとして、ライセンスやアクセスの問題、ログイン時の混乱、デモ環境の不具合を挙げています。対策は、事前にIT部門と確認すること、資料とアクセス手順を前もって配ること、デモ環境を事前に確認することです。

エージェントに社内資料をつなぐ場合は、見せてよい範囲かどうかを先に確認してください。AI は、もっともらしい間違いを答えることがあります（ハルシネーション）。作ったエージェントの答えは、利用者が確かめてから使います。

06おわりに

記事の結論は、「まず何かを作ってもらう」のではなく、「本当の困りごとを1つ解決する」ことから始める、というものでした。エージェントを作ることは、価値を実感した結果であって、出発点ではないということです。

自分の職場に置き換えると、最初の一歩は、全員への研修ではなく、1つのチームから始めることかもしれません。そのチームの実際の仕事に合うエージェントを一緒に作り、うまくいった点を次のチームに伝えます。これは、Agent Builder に限らず、新しい道具を職場に広げるときにも使える進め方です。
