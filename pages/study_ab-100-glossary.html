AB-100 ってどんな試験？

料金・時間・合格点などの基本情報と、何が問われるかをまとめました。数字は 2026-11-02 に公式ページで確認したものです。

ひとことで言うと「AI とエージェントで業務をどう変えるか」を設計する人の試験です

エージェントの基本

エージェント（AI エージェント）★ 重要AI agent

目標を与えると、状況を読み取って判断し、ツールを使って作業まで進める AI です。質問に答えるだけのチャットと違い、レコードの更新やメール送信など「実行」まで担えます。

ツボAB-100 の主役です。人がどこまで関わるかで、タスク型・自律型などに分かれます（分野2）。

[70][7]

エージェントファースト★ 重要Agentic-first

業務プロセスを考えるとき、「まずエージェントに任せられないか」から設計する考え方です。人は判断・承認・例外対応など、価値の高い部分に集中します。

ツボ受験者像に「エージェントファーストのソリューションを設計し、そのロードマップを定義する」とあり、試験全体の前提になる考え方です。

[1]

マルチエージェント★ 重要Multi-agent solution

複数のエージェントが役割を分けて、1つの仕事を進める構成です。受付役のエージェントが、専門のエージェントに仕事を振り分けます。

ツボ公式も「いつも必要なわけではない」と注意しています。小さな用途なら、1つのエージェント＋子エージェントで足ります。

[1][25]

オーケストレーションOrchestration

「どの順番で、どのツール・ナレッジ・エージェントを使うか」を決めて、全体を指揮することです。Copilot Studio では生成型とクラシック型の2方式があります。

[19]

グラウンディング★ 重要Grounding

AI の回答を、社内文書や業務データなどの信頼できる情報に根拠づけることです。根拠のない作り話を減らし、自社に合った答えにします。

[1][22]

ナレッジソース★ 重要Knowledge source

エージェントが回答の根拠として参照する情報源です。SharePoint、Dataverse、Web サイト、アップロードしたファイル、外部システムなどがあります。

ツボCopilot Studio では、エージェント全体（ナレッジのページ）にも、トピックの中（生成回答ノード）にも追加できます。

[22]

RAG（検索拡張生成）Retrieval-augmented generation

質問に関係する情報を先に検索し、その結果を AI に渡して答えさせる方法です。グラウンディングの代表的なやり方です。

ツボ「最新の社内情報で答えさせたい」は、ファインチューニングではなく RAG が基本の答えです。

[5][22]

ハルシネーション（作り話）Hallucination

根拠がないのに、もっともらしい内容を AI が作ってしまうことです。

ツボ対策はグラウンディング、テストでの正確さのチェック、重要な操作の前の人による確認です。

[5][33]

モデルとプロンプト

LLM（大規模言語モデル）Large language model

大量の文章で学習した、文章を理解して書く AI モデルです。会話・要約・推論など幅広くこなします。

[1]

SLM（小規模言語モデル）★ 重要Small language model

規模が小さく、軽くて安く速いモデルです。Microsoft の Phi などがあり、特定の業務に合わせて調整して使うこともあります。

ツボ出題範囲に「カスタマイズした SLM のユースケースを考える」があります。単純で大量の処理、低コスト・低遅延が条件なら候補になります。

[1][42]

プロンプトPrompt

AI への指示文です。何をしてほしいか、どんな情報を使うか、どんな形で答えてほしいかを書きます。

[18]

プロンプトエンジニアリング★ 重要Prompt engineering

欲しい答えが返るように、指示文の書き方を工夫する技術です。役割・目的・条件・出力の形をはっきり書くのが基本です。

ツボAB-100 では、自分で書く人ではなく「組織にガイドラインと手法を示す人（アーキテクト）」として問われます。

[1][18]

トークンToken

モデルが文章を処理するときの細かい単位です。料金・速度・一度に読める量（コンテキストの上限）に関係します。

[41]

推論モデルReasoning model

答える前に段階的に考えるモデルです。複雑な判断に強い代わりに、時間とコストが多くかかります。

ツボCopilot Studio では「ディープリーズニング」として追加できます（分野2）。

[29][1]

AI ソリューションの計画

要件を分析し、AI 戦略を決め、費用対効果を見積もる分野です。配点がいちばん大きく、2026-11-16 の更新で比重が増えました。

要件を分析する

エージェントを使う3つの場面★ 重要Task automation / data analytics / decision-making

出題範囲は、エージェントの使いどころを「タスクの自動化」「データ分析」「意思決定」の3つで評価するよう求めています。定型作業の代行、データから傾向を読む、提案や判断の支援、と整理します。

[1][5]

グラウンディング用データの5つの観点★ 重要Accuracy, relevance, timeliness, cleanliness, availability

エージェントの根拠にするデータは「正確さ」「関連性」「新しさ（適時性）」「きれいさ（重複や誤りがない）」「使えること（アクセスできる）」で確認します。

ツボ「古いマニュアルが混ざって答えが古い」なら新しさ、「重複した文書で答えがぶれる」ならきれいさ、のように症状から観点を選びます。

[1]

AI 向けのデータ基盤AI data foundation

業務データを、ほかの AI システムからも使える形に整えておくことです。置き場所・形式・権限・説明（メタデータ）をそろえます。

ツボ出題範囲の「他の AI システムで使えるようにデータを整理する」に当たります。CAF にもデータ基盤の章があります。

[1][6]

Microsoft Fabric と Fabric データエージェントMicrosoft Fabric / Fabric data agents

Fabric は Microsoft の分析基盤です。Fabric のデータエージェントは、Fabric のデータに自然な言葉で質問できるエージェントで、Copilot Studio から接続することもできます（プレビュー）。

[7][25]

Copilot コネクタ★ 重要Microsoft 365 Copilot connectors

Microsoft 365 の外にあるデータを、Copilot と Microsoft Search で使えるようにする仕組みです。データを Microsoft Graph に取り込む「同期型」と、MCP でその都度取りに行き取り込まない「フェデレーション型」があります。

ツボ「データを複製したくない」「常に最新が必要」ならフェデレーション型です。旧名は Microsoft Graph コネクタ。

[15]

AI 戦略を設計する

CAF（クラウド導入フレームワーク）の AI 導入★ 重要Cloud Adoption Framework for Azure

Microsoft が公開している、組織でクラウドと AI を導入するための手引きです。AI では「計画（AI planning）→ 準備（AI ready）→ 統制・保護・管理（govern, secure, manage）」の段階を踏みます。

ツボ最初にリーダーが目的と優先順位を示し、ガバナンスを中央で決めるのが「土台」です。

[6][1]

SaaS・PaaS・IaaS の選び方AI decision tree

CAF は「必要なカスタマイズができる中で、運用の手間がいちばん少ないもの」を選ぶよう勧めています。SaaS（Copilot Studio などのローコード）→ PaaS（Microsoft Foundry）→ IaaS（GPU やコンテナ）の順に、自由度も運用の負担も増えます。

ツボCAF には「Azure のインフラ（IaaS）を最初の選択肢にしない」と明記されています。

[6][7]

AI センター・オブ・エクセレンス（AI CoE）★ 重要AI Center of Excellence

全社の AI の方針・標準・責任ある AI の要件を中央で決めるチームです。事業部門は、その枠の中で AI の活用を進めます。

ツボ出題範囲は「Microsoft AI CoE の要素を取り入れる」です。中央で決めること（方針・標準）と、現場に任せることを分けます。

[6][1]

AI 戦略（AI 憲章）AI strategy / charter

組織の優先順位、誰が何を決めるか（意思決定の権限）、AI 投資の価値の測り方を書いた文書です。経営層が方向を示して後押しします。

[6]

事前構築済みエージェント★ 重要Prebuilt agents

Microsoft が用意した、すぐ使えるエージェントです。Microsoft 365 Copilot の Researcher や Analyst、Dynamics 365 の営業・サービス・財務の各エージェントなどがあります。

ツボアーキテクトの基本は「作る前に、既製品で足りないか確かめる」です。

[1][16][56]

Researcher と AnalystResearcher / Analyst agents

Microsoft 365 Copilot に用意されたエージェントです。Researcher は Web と社内の情報を使って複数ステップの調査をし、出典つきのレポートを作ります。Analyst は Excel などのデータ分析に向きます。

ツボResearcher の中身（ロジック）は利用者側で変えられません。

[16]

カスタムエージェントを作るか、Copilot を拡張するか★ 重要Build custom agents vs extend Microsoft 365 Copilot

社員が Microsoft 365 の中で使い、Copilot の頭脳（オーケストレーターとモデル）のままでよいなら「拡張（宣言型エージェント）」。独自のモデルや処理の流れ、社外向けのチャネルが必要なら、カスタムエンジンエージェントや Copilot Studio・Foundry で作ります。

[10][1][9]

宣言型エージェント★ 重要Declarative agent

Microsoft 365 Copilot のオーケストレーターとモデルをそのまま使い、指示・ナレッジ・アクションを「宣言」して作るエージェントです。Agent Builder や Copilot Studio で作れます。

ツボ「Microsoft 365 のセキュリティとコンプライアンスの範囲内で、手早く業務向けに」なら宣言型です。

[11][10]

カスタムエンジンエージェント★ 重要Custom engine agent

処理の流れ（オーケストレーション）と AI モデルを自分で選んで作るエージェントです。Copilot Studio、Microsoft 365 Agents SDK、Teams SDK、Microsoft Foundry で作れます。

ツボ「独自モデル」「独自の処理の流れ」「業務システムとの複雑な連携」「先回りして動く自動化」ならカスタムエンジンです。

[12][10]

カスタム AI モデルを作るタイミング★ 重要When to create custom AI models

まず既製のモデル＋プロンプト＋グラウンディング（RAG）で試し、それでも品質・書式・専門性・コストの要件を満たせないときに、ファインチューニングやカスタムモデルを考えます。

ツボファインチューニングは「振る舞い・書式・専門的な言い回し」を覚えさせるもの。最新の知識を入れたいなら RAG です。

使うときの注意点

  • 範囲
    出題範囲は 2026年11月16日版（英語）です

    日本語などの翻訳版は、英語版の約8週間後に更新されます。日本語で受ける場合は、しばらく更新前の範囲のことがあります。受験前に study guide の日付を確認してください。[1][3]

    公式ページで国を「日本」にしたときの表示です。為替や改定で変わることがあり、キャンペーンや割引は含みません。正確な金額は予約画面で確認してください。[3]

    よく使われているプレビュー機能が出ることもあります。このページでは、プレビューの機能にそう書いています。[1]

  • 要約
