Research memo / Copilot Studio

移管したエージェントが動かないとき

調査日2026-09-29
対象Copilot Studio のエージェント（ソリューションで移管）
前提同一テナント内の別環境へ移管し、インポート後に動かない

動かなくなる原因のほとんどは、「箱に入らない設定」か「環境ごとに違う設定」のどちらかです。

ソリューション（引っ越し用の箱）で運ばれるのは、指示やトピック、フローの定義といったエージェントの中身までです。接続（外部サービスへのログイン情報）、ユーザー認証、チャネル、公開状態、共有は運ばれないので、移行先で設定し直す必要があります。

もう一つの落とし穴は、同じテナント（同じ会社の Microsoft 365）の中でも、データポリシー、生成AIの地域設定、利用枠（Copilot クレジット）は環境ごとに別々だという点です。移行元で許可されていたことが、移行先では止められていることがあります。

切り分けは「新環境で公開したか」→「新環境のテスト画面で動くか」の2問から始めるのが近道です。テスト画面で動くなら入口（チャネル・認証・共有）、動かないなら中身・つなぎ・環境設定の問題、と半分に絞れます。

まず押さえる仕組み 何が運ばれて、何が運ばれないか

移管後の不具合は、下の3つの置き場のうち右の2つで起きます。ここを先に頭に入れておくと、原因の当たりが付けやすくなります。

箱に入って運ばれる

ソリューションに入れておけば移行先に届く

  • エージェント本体（指示、トピック、ナレッジの設定、ツール）
  • ソリューションに入れた Power Automate フロー、カスタムコネクタの定義
  • 接続参照・環境変数の「定義」
  • Dataverse テーブルの「形」（データの中身は別の道具で移す）[11]

箱に入らない

移行先で設定し直す

  • 接続そのもの（Outlook や SharePoint へのログイン情報）[10]
  • ユーザー認証の設定 [14]
  • チャネル（Teams、Web サイトなど）の設定 [14]
  • 公開状態と共有。公開するまで共有もできない [14]
  • アイコン（反映まで最大24時間）、トピックのコメント [14]

環境ごとに持っている

管理者が環境単位で決めている設定

  • データポリシー（DLP：使ってよいコネクタのルール）[6]
  • 生成AI機能の「リージョン間でのデータ移動」「Bing 検索」[5]
  • Copilot クレジットの割り当て、従量課金プランへのリンク [12][13]
  • マネージド環境のポリシー（アンマネージドのカスタマイズをブロック など）[17]

新環境のエージェントは「中身が同じ別のエージェント」です。インポートすると、新しい環境に新しいエージェントが作られます。そのため、旧環境で作った Teams アプリや Web サイトの埋め込みコードは、旧環境のエージェントを指したままです（仕組みからの推論）。「Teams から話しかけたら古いほうが答えていた」という取り違えは、まずここを疑ってください。

同一テナントなら、テナント全体の設定は原因候補から外しやすいです。作成者のセキュリティグループや「AI 機能つきエージェントの公開」の許可はテナント単位の設定なので、移行元で公開できていたなら同じはずです[18]。ただし、移行先で作業する人が変わった場合は、その人のライセンスを確認してください。

切り分けの手順 上から順に進める

順番に意味があります。前の問いで原因が見つかれば、そこで止めて直してから再確認してください。

  1. STEP 1

    症状を4つのどれかに当てはめる

    「動かない」のままだと原因が絞れません。どこで、何が起きたかを1文にします。画面に出たメッセージとエラーコード（不具合の種類を表す英単語の名札。例：FlowActionException）は必ず控えてください。

    公開ボタンでエラーテスト画面でもエラーテスト画面では動くが Teams / Web で動かない一部の質問だけ失敗する
  2. STEP 2

    新環境で「公開」したかを確認する

    インポートしただけでは、利用者向けの最新版がありません。LatestPublishedVersionNotFound は公開で解消します。「Sorry, the bot can't talk for a while」と出る AIPluginOperationNotFound は、インポートやソリューション展開の経由で公開されたときに起こりうると公式に書かれており、対処は再公開です[3]。

    公開ボタンでエラーが出る場合は、ソリューションに部品が足りない可能性が高いです。下の早見表の A を見てください[1]。

  3. STEP 3

    新環境のテスト画面で同じ質問を試す

    Copilot Studio の「エージェントをテスト」の画面です。作成者がテストすると、エラーコードと詳しい説明が表示されます[3]。ここで結果が分かれます。

    動く →中身は無事です。STEP 5（入口の確認）へ進んでください。
    動かない →中身・つなぎ・環境設定のどこかです。STEP 4 へ進んでください。
  4. STEP 4

    エラーコードから原因を引く

    控えたエラーコードを下の症状別の早見表で探します。あわせて「トピックチェッカー」でエラーの出ているトピックがないかも確認します[3]。フローを呼ぶ場面だけ失敗するなら、Power Automate 側でフローがオンになっているか、実行履歴に失敗が出ていないかを見ます。

  5. STEP 5

    入口（認証・チャネル・共有）を確認する

    ① 設定 > セキュリティ > 認証 が空や既定のままになっていないか[14]。② 利用者が使っている Teams アプリや Web の埋め込みが、新しいエージェントのものか。③ 公開後に共有をやり直したか[14]。

  6. STEP 6

    移行元と移行先の環境設定を並べて比べる

    ここまでで見つからなければ、環境ごとの設定の差を疑います。多くは管理者しか見られない画面なので、下の「管理者に確認してもらう設定」の表をそのまま渡して、移行元と移行先で違いがないかを見てもらってください。

表示されたメッセージやエラーコードで引いてください。スマホでは表を横にスクロールできます。

症状・表示考えられる原因対処確度・根拠
A　公開・中身
公開時に IdentifierNotRecognized などの式エラー、「要素が無効または見つからない」 フロー・環境変数・接続参照がソリューションに入っていない 移行元で、エラーの出た部品とエージェント本体に「詳細」→「必要なオブジェクトを追加」→ 再エクスポート → 再インポート 公式に記載[1]
「Sorry, the bot can't talk for a while」（AIPluginOperationNotFound） インポートやソリューション展開の経由で公開されたときに起こりうる 新環境でエージェントを公開し直す 公式に記載[3]
LatestPublishedVersionNotFound 新環境でまだ公開していない 公開する 公式に記載[3]
移行元で後から足したトピックやツールが、移行先にない 移行先に届くのは、エクスポートした時点の状態だけ 「必要なオブジェクトを追加」→ 再エクスポート → 再インポート。今後は優先ソリューションを設定しておく 公式に記載[2]
RedirectToNonExistentDialog 移動先のトピックが存在しない 移動先のトピックを用意するか、移動（リダイレクト）の部品を外す 公式に記載[3]
B　フロー・接続・環境変数
フローを呼ぶ場面だけ失敗する（FlowActionException など）、フローがオフのまま 接続参照に新環境の接続が入っていない。または、インポートした人が接続を使う権限を持たず、フローがオンにならなかった 接続参照に新環境の接続を設定し、フローをオンにする。接続の持ち主がオンにするか、接続をその人に共有する 公式に記載[9][10]
FlowMakerConnectionBlocked 作成者の接続でフローを実行することを、管理者が禁止している Power Automate でフローを「実行専用ユーザー」として共有する 公式に記載[3]
エラーは出ないが、旧環境のデータ（SharePoint リストなど）を見ている。または値が空で失敗する 環境変数の「現在の値」がソリューションに同梱され、旧環境の値のまま運ばれた。または値が未設定 移行先で環境変数の値を新環境用に入れ直す。次回は「現在の値」をソリューションから外してからエクスポートする 公式に記載[11]
ツール呼び出しで HTTP401 / 403 / 404 接続の資格情報切れ、権限不足、ID や URL の誤り（環境の選び間違いを含む） 接続を作り直す、権限を確認する、手入力の ID ではなく一覧から選ぶ形にする 公式に記載[3]
C　環境の設定
公開できない、または DataLossPreventionViolation 新環境にかかるデータポリシーが、使っているコネクタやチャネルをブロックしている。ポリシーはテナント全体だけでなく環境単位でも作れるため、環境ごとに内容が違うことがある 管理者にポリシーを確認してもらう。違反の詳細は Excel で取得できる。「サインイン必須」のポリシーなら認証を設定する 公式に記載[3][6][7][8]
生成AIの回答や生成オーケストレーションが動かない（GenerativeAINotAvailable） 新環境で「リージョン間でのデータ移動」がオフ。環境の地域によっては、これがないと生成AI機能が使えない 管理センターで対象環境の「生成 AI 機能」を編集し、「リージョン間でのデータ移動」をオン。できなければ生成AI機能を使わない設計にする 公式に記載[4][5]
「This agent is currently unavailable. It has reached its usage limit」（EnforcementMessageC2） 新環境で使える Copilot クレジット（利用枠）がない。または従量課金プランにリンクされていない 容量を割り当てるか、従量課金プランに環境をリンクする。対応後5分ほどで復旧する 公式に記載[3][12][13]
エージェントは答えるが、エージェントフローだけ動かない 環境の前払い容量を使い切ると、新しいエージェントフローの実行が止められる 容量の再割り当て、追加購入、または従量課金の有効化 公式に記載[12]
アップロードしたファイルのナレッジで 0x80072042 / 0x80048d0b マネージドで移管し、移行先で「アンマネージドのカスタマイズをブロック」のポリシーが有効 移行元のソリューションに DVFileSearch の UnstructuredFileSearchSkill を追加し、マネージドで再エクスポート 公式に記載[17]
D　認証・チャネル・共有
サインインを求められる、AuthenticationNotConfigured ユーザー認証の設定は移管で引き継がれない 設定 > セキュリティ > 認証 を設定し直す。手動認証なら、クライアント ID やシークレットなどを入れ直す 公式に記載[3][14]
Teams でだけ自動サインイン（SSO）が失敗する Teams の SSO は、アプリ登録の「アプリケーション ID URI」に Teams 側のアプリ ID を入れる仕様（api://botid-{ID}）。新しいエージェントは ID が変わるため、旧 ID のままだと合わない 新しいエージェントの Teams アプリ ID で、アプリ登録と Teams チャネルの SSO 設定を更新する 推論[15]
Teams や Web から話しかけると旧エージェントが答える、または反応がない チャネルの設定は移管されず、旧 Teams アプリや旧埋め込みコードは旧環境のエージェントを指したまま 新しいエージェントでチャネルを設定し直し、Teams アプリや埋め込みコードを差し替える 推論[14]
共有したはずの人が使えない 共有の設定は運ばれない。公開前は共有できない 公開してから共有し直す 公式に記載[14]
E　ナレッジ・複数エージェント
SharePoint のナレッジから答えが返らない（エラーも出ない） 利用者に閲覧権限がないと、エラーを出さずに「見つからない」扱いになる。認証のスコープ（許可の範囲）不足も原因になる 利用者がそのファイルを直接開けるか確認する。手動認証なら Sites.Read.All と Files.Read.All を設定する 公式に記載[16]
ConnectedAgentBotNotFound / ConnectedAgentBotNotPublished 呼び出す子エージェントが同じ環境にない、または未公開 子エージェントも同じ環境に移して公開する 公式に記載[3]

解決策 立て直すときの順番

原因が一つに絞れないときは、次の順で上から潰すと手戻りが少なくなります。手順そのものは、同じ棚の「Copilot Studio エージェントの環境移管ガイド」のスライドにまとめています。

  1. 部品の不足を埋める移行元でエージェント本体に「必要なオブジェクトを追加」し、フロー・接続参照・環境変数が入っているか確認してから再エクスポートする [1][2]
  2. 接続をつなぎ直し、フローをオンにするソリューション内の接続参照を開いて新環境の接続を選ぶ。フローがオフなら、接続の持ち主がオンにする [9][10]
  3. 環境変数の値を新環境用にするSharePoint のサイト URL や宛先アドレスが旧環境のままになっていないか、一つずつ確認する [11]
  4. ユーザー認証を設定し直すTeams で SSO を使う場合は、新しいエージェントの ID でアプリ登録を更新する [14][15]
  5. 新環境で公開するインポート経由の公開で不調なら、もう一度公開する [3]
  6. チャネルを差し替え、共有し直すTeams アプリや Web の埋め込みを新しいエージェントのものに入れ替え、利用者に共有する [14]
  7. 環境の設定を管理者と照合するデータポリシー、生成 AI 機能、Copilot クレジットを移行元とそろえる [5][6][12]

次回は環境変数の値を外して書き出す

「現在の値」をソリューションから外してエクスポートすると、インポート時に新しい値の入力を求められます。旧環境の値が紛れ込む事故を防げます[11]。

移行先の管理設定を先にそろえる

データポリシー、生成 AI 機能、クレジットの割り当ては、インポートより前に管理者と確認しておくと当日に止まりません。

最初からソリューションの中で作る

優先ソリューションを設定しておくと、後から足したトピックやツールも自動で箱に入ります[2]。

管理者に確認してもらう設定 移行元と移行先で比べる

すべて Power Platform 管理センター（admin.powerplatform.microsoft.com）で確認できます。画面の名前は更新で変わることがあります。

設定見る場所違うと起きること根拠
データポリシー セキュリティ > データとプライバシー > データ ポリシー。テナント全体のものと、環境単位のものの両方を見る コネクタやチャネルがブロックされ、公開できない。サインイン必須になる [6][7][8]
生成 AI 機能 管理 > 環境 > 対象の環境 >「生成 AI 機能」の編集。「リージョン間でのデータ移動」「Bing 検索」 生成 AI の回答や生成オーケストレーションが使えない [4][5]
Copilot クレジット ライセンス > Copilot Studio。環境への割り当てと、使い切ったときの扱い（テナントの残りから使う／従量課金へ） 「使用上限に達しました」の表示。エージェントフローの停止 [12]
従量課金プラン 課金プランに新環境がリンクされているか。従量課金は運用環境とサンドボックス環境が対象 従量課金のつもりが課金されず、利用枠切れで止まる [13]
マネージド環境のポリシー 「アンマネージドのカスタマイズをブロック」が有効か ファイルのナレッジの準備に失敗する [17]

注意点 説明するときに外さないこと

  • このメモは同一テナント内の移管が前提です。テナントをまたぐ場合は、アプリ登録やナレッジの参照先まで作り直しになり、範囲が大きく広がります。
  • 早見表の「推論」の行（Teams の SSO、旧チャネルが旧エージェントを指す件）は、公式の仕様から導いた見立てです。公式にこの症状として書かれているわけではないので、実機で確かめてから結論にしてください。
  • 画面のボタン名、ライセンスの条件、生成 AI の提供地域は更新が早い領域です。作業の前に根拠のページで最新の記載を確認してください。
  • Copilot Studio 本体のドキュメントのうち [7][8][14][15] は、この調査の環境から本文を直接開けず、検索結果の要約で内容を確認しました。そのため最終更新日を載せていません。
