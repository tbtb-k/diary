# ほしくずサバイバー：ゲームの芯（設計メモ）

毎朝の改良は、このメモに合っているかで判断します。**「3つの芯」と「やらないこと」は、持ち主（tbtb-k）が OK したときだけ変えます。** それ以外の「今の中身」「バランスの目安」は、改良に合わせて書きかえてかまいません。

## ひとことで

光の武器で敵の群れをなぎ払い、5分を生き延びてボスを倒す、スマホ縦持ち・片手で遊ぶサバイバー系ゲーム。

## 3つの芯

1. **群れをなぎ払う気持ちよさ**：後半ほど「強くなった！」と感じられること。敵の壁に押しつぶされるだけの展開にしない。
2. **3択で自分だけの強さを組み立てる楽しさ**：毎回ちがう組み合わせになり、「次はあの組み合わせで」と思えること。
3. **片手で1回5〜7分、すぐ「もう1回」**：ルールの説明なしでも遊べて、負けてもすぐ再挑戦したくなること。

## 遊ぶ人

- 持ち主（エンジニアではない）。通勤中や待ち時間に、スマホを縦に持って親指1本で遊ぶ。
- サイトの一覧（https://tbtb-k.github.io/diary/ ）から開く。

## 守ること（技術の決まり）

- HTML1ファイル（`pages/game_hoshikuzu-survivor.html`）。描画は Canvas 2D。
- 外から読み込むのは Google Fonts（Orbitron・M PLUS Rounded 1c）だけ。画像・音声ファイルは使わない。模様はコードで描き、音は Web Audio で合成する。
- 操作は「画面のどこでも指をおいてすべらせる」。パソコンは矢印キー／WASD。傾きセンサー・カメラ・マイクは使わない。
- 1プレイは7分以内に終わる（ボスは5:00に出る）。
- 記録は localStorage（キーは `hs-` で始める）。読み書きは必ず try/catch。前の版の記録を消したり読めなくしたりしない。
- ファイルの大きさは 400KB まで。スマホで60fpsを目安にし、重いときは自動で画質を下げる仕組みを残す。
- テスト用の窓口 `window.__game`（start / sim / state / debug）を残し、新しい要素を足したら `tests/playtest.js` でも確かめる。
- ゲームの中の文章は、やさしいタメ口（〜だよ、〜してね）。

## 世界観と見た目

- ネオンの宇宙。暗い紺〜紫の背景に、光る図形が飛び交う。
- 色の役割：シアン `#3ef2ff`（自機・ほしくず・パルス）、ピンク `#ff4fb0`（ふつうの敵・ノヴァ）、紫 `#b48cff`（オービット・硬い敵）、黄 `#ffd84a`（スパーク・速い敵・レベルアップ）、緑 `#5dff9b`（回復・撃ってくる敵）、オレンジ `#ff7a3d`（強敵）、赤 `#ff3b5c`（ボス）。
- 新しい敵や武器も、この配色と「光る図形」の見た目にそろえる。

## 今の中身（Day 1 時点）

- 武器（最大Lv6）：パルスショット（近くの敵に弾）、オービット（回る玉）、ノヴァ（周りに光の輪）、スパーク（跳ねる雷）
- 補助（最大Lv5）：出力アップ、冷却ユニット、推進エンジン、装甲、引力フィールド、ナノリペア
- 敵：ドリフター（ピンクの矢じり）、ダーター（黄色の速いひし形）、ブルート（紫の硬い四角）、シューター（緑の六角形、弾を撃つ）
- 流れ：1分ごとに「RUSH!」（まわりから敵の輪）、2:30 と 3:45 に強敵（オレンジの星）、5:00 にボス「ブラックスター」（輪の弾幕と突進）。ボス戦ではパルスとスパークがボスを優先して狙う。
- スコア：生き延びた秒×10 ＋ 撃破×2 ＋ レベル×40 ＋ クリアボーナス（早く倒すほど多い）

## バランスの目安（自動テストのボットで確かめる）

| 項目 | 目安 | Day 1 の値 |
|---|---|---|
| 何もしない（idle） | 3分以内に倒される | 平均 33秒 |
| 自動操作（smart）の平均 | 150秒以上 | 平均 373秒 |
| 自動操作のクリア | 4回中 2〜4回 | 4/4 |
| ボス戦の長さ | 40〜90秒 | 50〜95秒 |

ボットは人より正確に逃げるので、人にはもう少し難しく感じられるはずです。持ち主の「むずかしい／かんたん」の感想があれば、そちらを優先して目安を書きかえます。

## やらないこと

- ジャンルを変える・別のゲームに作り変える
- オンライン要素（ランキングの送信、ログイン、外部サーバー）
- 課金風の要素、ガチャ、広告、毎日ログインしないと損をするしくみ
- 長いチュートリアル、文字だらけの画面
- 1回の改良で、遊び方が大きく変わる変更を何個も入れること
